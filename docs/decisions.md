## 2026-08-08 — мирные жители: lifecycle, уязвимость, постановка в мир

**Контекст.** Разведка P-02 (полный отчёт см. историю сессии): цикл жизни один на всех, развилка только `Fraction == Undead`; человек после смерти восстаёт нежитью за 60–600 с; флага «не восстаёт» нет; активности/расписания мирной рутины готовы (образец `Npc_Villager`), но активности «работать у точки» нет; именованного спавна нет — точки роллят стойку/уровень/редкость; безопасной зоны как механики нет.

**Варианты и выбор (Todd):**
1. **Lifecycle**: (А) режим в `NpcLifecycleConfig` — рекомендация агента; (Б) отдельный lifecycle-класс; (В) данными-таймерами. → **Выбрано Б: отдельный класс.** Мотив опции: оправдан, если мирный цикл растёт своими состояниями — считаем это заявкой на рост (плен/болезнь/быт).
2. **Уязвимость**: ключевые жители **смертны, но встают живыми** по таймеру; нежитью не восстают, сжечь нельзя, финальной смерти нет. Механика «безопасной зоны» отклонена (достаточно leash+wander); «полное бессмертие/декорация» отклонено (противоречит «игрок не центр вселенной»).
3. **Постановка в мир**: **авторский именованный спавн** — фиксированный id и фиксированные характеристики из данных, без роллов. Прецедент «как торговец» (точка с одним id, но роллящая статы) отклонён.

## 2026-08-08 — центральная втулка колеса

Четвёртый узел вида `Start` (id `Start`, позиция (0,0), без стойки и способности, связан с тремя стоечными сидами) — **осознанная втулка колеса, подтверждено владельцем**. Сейчас `Validate()` счёл бы её тройной ошибкой (старт без стойки; узел без способности; 4 старта при `StartPointCount = 3`), но валидация против авторской разметки не гоняется ни одним тестом — расхождение молчит. Правила вида узла приводятся к реальности (P-19): втулка законна, в счёт стоечных стартов не входит; схема данных не меняется (замороженный инструмент разметки продолжает писать её как `Start`).

## 2026-08-09 — архитектурный проход по способностям и аугментам (решения Todd)

Разведка (два отчёта: карта+покрытие, транзитивность) подтвердила: 83/134 записей жёстко привязаны abilityId; 12+ записей мертвы/падают; транзитивность работает только там, где способность сама рождает эффект; 14 позиций списка `Аугменты.md` невыразимы. Решения:

1. **Транзитивность — поэтапно**: волной N — канал «райдер видит способность» (расширение контракта импакт-райдера, ленивые фабрики эффектов от `AbilityParameterSet`); отдельной волной — след способности на эффекте (AbilityId/CastId) для «продлить/усилить СВОЙ яд» и ability-фильтров. Конечное состояние то же, что у одномоментного варианта; выбрана этапность ради собираемости.
2. **Общие ключи параметров + семантика владельца**: `AbilityParameter` расширяется общими понятиями (длительность/эффективность/стаки накладываемого, число атак/снарядов/зарядов…), регистрирует их способность/семейство-владелец; приватные ключи остаются именному. «Тег обещает подгонку, не работу» сохраняется.
3. **Поведение из данных — для обобщаемых**: реестр «behaviour → фабрика» + эффект по id из общего провайдера с properties (расширение подхода GrantEffectProvider). Именные (подмена стратегий) остаются кодом.

Попутно: баг «цель испытания не спавнится» — опечатка в сцене (`Trial_Ground` vs `Trial_Grounds`), починка — поле Point Id в инспекторе (владелец).
