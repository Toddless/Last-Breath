## 2026-08-09 — архитектурный проход по способностям и аугментам (решения Todd)

Разведка (два отчёта: карта+покрытие, транзитивность) подтвердила: 83/134 записей жёстко привязаны abilityId; 12+ записей мертвы/падают; транзитивность работает только там, где способность сама рождает эффект; 14 позиций списка `Аугменты.md` невыразимы. Решения:

1. **Транзитивность — поэтапно**: волной N — канал «райдер видит способность» (расширение контракта импакт-райдера, ленивые фабрики эффектов от `AbilityParameterSet`); отдельной волной — след способности на эффекте (AbilityId/CastId) для «продлить/усилить СВОЙ яд» и ability-фильтров. Конечное состояние то же, что у одномоментного варианта; выбрана этапность ради собираемости.
2. **Общие ключи параметров + семантика владельца**: `AbilityParameter` расширяется общими понятиями (длительность/эффективность/стаки накладываемого, число атак/снарядов/зарядов…), регистрирует их способность/семейство-владелец; приватные ключи остаются именному. «Тег обещает подгонку, не работу» сохраняется.
3. **Поведение из данных — для обобщаемых**: реестр «behaviour → фабрика» + эффект по id из общего провайдера с properties (расширение подхода GrantEffectProvider). Именные (подмена стратегий) остаются кодом.

Попутно: баг «цель испытания не спавнится» — опечатка в сцене (`Trial_Ground` vs `Trial_Grounds`), починка — поле Point Id в инспекторе (владелец).

## 2026-08-10 — оси эффективности/длительности и Ярость (решения Todd)

1. **Длительность и эффективность — разные оси, не сливать.** Эффективность = множитель ЗНАЧЕНИЙ накладываемого содержимого (баф/дебаф/урон/восстановление; пример владельца: Эгида жизни с +эффективностью восстанавливает 54% вместо 35%), сегментирована по роду содержимого, как в дизайн-списке («Эффективность бафа», «…дебафа», «…восстановления» — отдельные записи). Обобщающего ключа «накладываемый эффект» не будет; «Длительность накладываемых эффектов» из списка читается как агрегат — аугмент двигает длительности всех накладываемых эффектов способности (механизм «запись двигает семейство ключей» — проектировать в волне C).
2. **`BerserkFury.FuryDuration` → общий `Duration`, переносим**: «+длительность бафа» на Ярости станет рабочим и будет продлевать и жжение HP — «игрок решает сам». Запись `Augment_Fury_Duration` остаётся Subtract-ручкой цены на том же общем ключе (сознательный соперник-антагонист).

## 2026-08-10 — ответы Todd на вопросы B-3

1. **Тег `debuff` раздаём СЕЙЧАС**: дебафные способности (Глыба льда, Ледяная эгида, Глубокая заморозка, Двойной удар) получают тег и чтение эффективности своего дебафа; форма чтения — по решению развилки п. 3.
2. **Примеры ≠ дизайн, если не сказано иначе** (правило в памяти агента). Семантика эффективности: дизайн-строка роллится, эффективность множит выпавший ролл (ролл 10 × эфф. 35% = 13.5; 20 → 27). «54% вместо 35%» был иллюстрацией механики, не спекой — отгруженное поведение B-3 (множитель поверх значения, 0.35×1.35=47.25%) корректно, диапазоны строк не трогаем до балансного прохода.
3. **Охват эффективности: ВСЕ числовые значения накладываемого содержимого, КРОМЕ длительности и количества стаков** (длительность — своя ось, стаки — своя). Развилка «свойство способности vs свойство эффекта» решена Todd: **свойство эффекта** (гибрид: ключ-источник и аугмент остаются на способности, значение штампуется на инстанцию эффекта при наложении, база `Effect` множит все объявленные числа, кроме длительности и стаков, одной точкой).
4. **Шесть буфф-способностей** (Арес, Эгида, Покрытие, Дикобраз, Жертва, Доспех) **доводим до владения `Effectiveness` — да, волна E.**
