## 1. Резюме

| Метрика | Значение |
|---|---|
| Находок в реестре | **90** (F-01 … F-90) |
| Опровергнуто аудитом (делать не надо) | **20 позиций** — раздел 3 |
| Находок в объёме прогона | 23 |
| Находок в бэклоге с обоснованием | 63 |
| Находок закрыто до плана (✅/⛔) | 4 |
| Задач | **18** (T-02 … T-19; T-01 отменена владельцем) |
| Волн | **5** + волна F (хвосты по решению владельца, подтверждена) |
| Критический путь | 5 задач, T-06 → T-07 → T-11 → T-15 → T-16 |

**Что делает прогон.** Закрывает шаги 3–6 «Предлагаемого порядка» техбазы: теги (уже закрыты, задач нет), развязку блокеров дерева, урезку атрибутов и домен дерева пассивок без UI. На выходе игра читает `PassiveTree.json`, узлы берутся и снимаются через отладочную консоль, вклад узлов виден в параметрах игрока и переживает сейв.

**Что вне прогона.** Сокеты и аугменты, разбор 189 записей реестра апгрейдов, аугменты-предметы, UI колеса и UI сокетов, данные дерева (~90 узлов, 3 старта, 36 сокетов), испытания сильных, конверсия N→1 в крафте, балансный пасс. `AbilityUnlockService` на узлы дерева — **следующая волна по решению владельца**, см. риск R-1.

### Инверсии — где логика зависимостей и здравый смысл расходятся

1. **T-08 (атрибуты) формально ничего не блокирует, но идёт рано.** Изолирована в обе стороны — по критериям это P2. Ставится P1 и в первую волну, потому что балансный шлейф дешевле сейчас: контента мало, дерева ещё нет, а после урезки все замеры узлов делаются уже на новой базе. Сделать её позже — значит дважды подбирать числа.
2. **T-16 (консоль) — P2 по критериям, но это критерий приёмки всего прогона.** Без неё «дерево работает» не проверяется ничем, кроме тестов. Стоит последней по зависимостям и первой по важности приёмки.
3. **T-06 (`IsStronger`) — L и «всего лишь» гигиена, но P0.** Не потому, что блокирует компиляцию, а потому, что после появления узлов, раздающих пассивки поверх предметных грантов, этот баг станет системным и будет выглядеть следствием реворка. Классический «всплывёт посреди переработки».
4. **T-09 (`Suppress`) — вне шагов 1–5, но в прогоне.** Формально это механика боя, а не дерево. Взята сюда решением владельца, потому что стат уже размечен четырьмя строками в `PassiveTree.json`: как только дерево заработает, игрок начнёт платить очки за ноль.
5. **T-03/T-04 — S и ничего не разблокируют, но в первой волне.** Дешевле сделать до агрегатора: T-12 обязана опираться на ленивые ручки, иначе агрегатор придётся писать дважды.
6. **T-01 отменена, но её мотив жив.** `HealthRecovery`, `ManaRecovery` и `CriticalDamage` по-прежнему не ограничены ничем, а T-08 снимает с них атрибутные источники — то есть на короткой дистанции риск раздутия даже падает. Владелец решил не вводить границы сейчас; вопрос возвращается на балансном шаге вместе с F-46.

## 6. Граф зависимостей и критический путь

```
Волна 1  T-02  T-03  T-04  T-05  T-06  T-07(←T-06)  T-08  T-09
                │     │     │      │
                │     │     │      └──────────────┐
                │     │     │                     │
Волна 2  T-10 ──┼─────┼─────┼─────────────────┐   │
                │     │     │                 │   │
Волна 3  T-11 ←─┴─────┴─────┴─────────────────┼───┘   (←T-10, T-06, T-07)
         T-12 ←───────────────────────────────┘       (←T-10, T-04, T-03)
           │
Волна 4  T-13 ←── T-11     T-14 ←── T-10, T-11     T-15 ←── T-11
           │                                          │
Волна 5  T-16 ←── T-11, T-12, T-13, T-15 ─────────────┘

Волна F  T-17 (нет)   T-18 ←── T-13   T-19 (нет)
```

Ацикличность: рёбра идут только «слева направо» по номерам волн; обратных нет. **T-07 → T-06 — единственное внутриволновое ребро** (T-08 → T-01 исчезло вместе с отменой T-01), разведено порядком запуска внутри волны 1.

**Критический путь:** `T-06 (L) → T-07 (M)` — самая длинная ветвь волны 1; после барьера `T-10 (L) → T-11 (L) → T-15 (M) → T-16 (M)`.

Длиннейшая цепочка — **5 задач: T-06 → T-07 → T-11 → T-15 → T-16**, из них две L. Отмена T-01 путь не укоротила: он никогда через неё не шёл.

**Что укорачивает путь:**
- **T-06 (`IsStronger`, L) — главный кандидат на разрез.** 40 файлов режутся на 2–3 пакета по 13–14 классов с непересекающимися файлами и параллелятся внутри волны 1. Стоимость: три отчёта вместо одного.
- **T-07 формально зависит от T-06 только через тесты.** Если T-06 разрезан, T-07 можно запускать после первого пакета — но тогда тесты владения могут падать по чужой причине. Не рекомендуется.
- **T-10 (L) не режется** — перенос модели атомарен: инструмент обязан собираться в конце задачи, а не в середине.
- **T-16 можно начать раньше** в части `passive tree` (только чтение бюджета) — но приёмочная ценность появляется только после T-13. Не рекомендуется.
