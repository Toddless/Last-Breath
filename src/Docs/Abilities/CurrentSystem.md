# Активные способности

Статус: описание существующей реализации. Основа и границы статической сверки — [в отчёте](../Guidelines/SystemDocumentationAudit.md).

## Устройство и поведение

- IAbilityBookComponent место обработки конкретных активных способностей сущности.
- Система улучшений активных способностей: Комбинированный подход из нескольких паттернов. Численные значения меняются при помощи декораторов. Логические выносятся в стратегии/отдельные небольшие модули.
- Активные способности: Комплексная система. Жизненный цикл Данные(json. Сейчас локально, потенциально получаемый от сервера) => Провайдер (Создание через фабрики) => Инстанция => Владелец. Вызов Ability.Execute - Единая точка для всех путей активации.
AbilityActivationContext меняется активационными мутаторами: Ability-scoped => Entity-scoped.
- ExecuteInternal - Delivery.
- Delivery: 1. Attacks - настоящие атаки. Для каждой Создаётся AttackContext через scheduler и проходит полный пайплайн обработки атак. 2. HitSequence - прямые хиты. Стратегия IHitSequenceStrategy отдает последовательность фактических касаний. 3. MulticastAbility<TPlan>: база способностей стойки интеллекта. Гарантирует бросок стадии и кумулятивный цикл. План - Generic-параметр живущий ровно один каст. Формы планов: CastPlanVolley - общий залп/крит в MulticastAbilityVoley, ChainPlan, AegisPlan, OverloadPlan.
- Riders - единый контракт вторичных эффектов: 1. IActivationRider - единожды на каст. 2. IImpactRider - на каждый импакт доставки. **Импакт несёт `required Source` (инстанция породившей способности — канал к её декорированным числам) и `required ImpactKind` — пять родов: `Attack` (пайплайн атак), `Hit` (прямое касание, включая отскоки IHitSequenceStrategy и доставку без урона), `Projectile` (снаряд залпа), `ChainJump` (прыжок цепи со своим falloff/счётом), `Splash` (вторичный урон, разлитый другим импактом). Род ставится в точке доставки и ниже не исправляется; забытая точка — ошибка компиляции, а не молчание.**
- Апгрейды (три рычага, комбинируемые): 1. Числа - декораторы: SimpleAbilityParameterDecorator поверх единого AbilityParameterSet (Core/Battle/Abilities; строковые ключи-константы: общие в AbilityParameter, свои — nested static class Parameters способности; регистрация значений в RegisterBaseParameters, каждый ключ автоматически = плейсхолдер описания). 2. Логика - подмена стратегий/фабрики. 3. Riders. Добавление: обёртки улучшений с райдерами и эффектами активации. 4. Апгрейд может ОДОЛЖИТЬ способности базовое значение параметра (`AbilityParameterSet.TryRegister` при установке, возврат при снятии; база уходит с последним одолжившим) — так податель делает транзитивность возможной на способности, не знавшей понятия.
