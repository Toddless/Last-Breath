## 2026-08-25 — Кейстоуны: формулировки и механизм (Todd)

1. **Сила K2 «невозможно уклониться»** — это РАСПЛАТА: у игрока с кейстоуном собственное уклонение больше не работает (не «его атаки неуклоняемы»). Хук на стороне защитника-носителя.
2. **Инт K1 «45% восст. маны → барьер»** — межпараметрический ВЫВОД: BarrierRecovery получает +45% от ПАРАМЕТРА ManaRecovery, мана не страдает (пример Todd: барьер-реген 15, мана-реген 100 → барьер-реген 60, мана 100). Готовая пассивка Mana_To_Barrier не подходит — нужен вывод параметра из параметра.
3. **Сила+Инт K2 «атаки не наносят физический»** — обнуление ТОЛЬКО в контексте удара; параметр PhysicalDamage сущности не трогается.
4. **Механизм кейстоунов** — направление Todd: в редакторе дерева нода несёт id + кастомные поля со значениями (баланс оттуда); в игре при взятии кейстоуна пассивки создаются на лету; «по факту все кейстоуны являются пассивками». Скоуп #202; открытая развилка проектирования: чисто-статовые кейстоуны (класс А, напр. живой keystone_6) — тоже через пассивки для единообразия или остаются данными.

## 2026-08-24 — Свежесть эффекта на текущем бойце (Todd, вариант В)

Следствие контракта Б-182: контроль, наложенный РЕАКЦИЕЙ на бойца посреди его же хода (заморозка слома Ледяной эгиды, freezeDuration 1), тратил свою длительность в конец этого же хода — ломающий не пропускал ничего. Решение — **общее правило**: эффект, наложенный на ТЕКУЩЕГО бойца в течение его хода **чужим источником**, не тратит длительность в конец этого хода (первый тик — следующий конец хода носителя). Рамка ведущего, согласованная с целью Б-182: селф-наложения под правило НЕ попадают (иначе селф-баф «на 1 ход» снова жил бы лишний ход — возврат только что убитого бага).

## 2026-08-18 — волна «эффекты + D»: решения по итогам разведки (Todd)

1. **Скверна НЕ обходит страж стадии** (анти-ваншот-пол боссов). Док уточнён владельцем: «наносит урон напрямую здоровью» — мимо щитов/барьеров/поглощений, но пол стадии уважает.
2. **`AllResistance` включает резист яда**; пенетрация яда — в `AllResistancePenetration` (зеркально стихиям).
3. **`AttackPureConversion` переименовываем** — сейв-строки этого мифика умирают (санкционировано).
4. **DoT-множители — вариант Б**: `EntityParameter.*DamageMultiplier` = стат сущности в базовой формуле тика; `ContextParameter.Poison/Burning/BleedDamage` остаются доп. строками предметов поверх базовых.
5. **Подавление** режет урон способностей независимо от типа: Sacred/Blight в составе урона способности режутся тоже.
6. **Дефолт классификации остаётся**: эффект без явного `IsHarmful` — баф.
7. Квирк «фактическая длительность = записанная + 1» в волне НЕ трогаем — отдельная осознанная задача после.
8. **`Calculations.CalculateSucceeded` устарел** (писался под «Невозможно уклониться»); подписчиков `TargetEvadedAttackEvent` нет (проверено владельцем) — сносим при вводе единой точки броска.
9. **К удаче обязателен антипод**: неудачливый бросок = два броска, худший. (Допущение ведущего, не оспорено: удача+неудача на одном броске взаимогасятся до одного броска.)
10. **Митигация тика яда — динамическая** (как броня у крови): резист читается на каждом тике текущим значением, снапшот морозит только пул → сниженный резист цели усиливает последующие тики.
11. **`EffectApplyingContext`** — подтверждённая роль staging-механизма (мутаторы правят копию, не оригинал); правка Ф0 расширяет поле `Damage` до снапшота компонентов В ЭТОМ ЖЕ месте, роль сохраняется.
12. **«Заряд» из списка = существующий `ChargeEffect`** детонации Статического доспеха (владелец перенёс описание в список) — новый эффект не заводить, сверить числа и завести в канон/реестр.
13. **Горение без огня в ударе, авторские источники** (удар Близнеца, Горящая ярость, Праведный гнев): остаются на синтетическом однородном огненном пуле — авторские числа, баланс не меняется.

Дополнение владельца: строка урона общая для всех стадий — Fire у ВСЕГО Армагеддона принят («всё ок»); владелец планирует отдельный проход по способностям с расстановкой типов урона.
15. **Нулевой пул DoT = отказ наложения**: стак, которому нечем тикать, не ложится (не занимает потолок и не мусорит UI).
16а. **Ф0-3, хвосты** (Todd): шансы-ручки контекста (`CooldownResetChance`/`FreeCastChance`) остаются ЧЕСТНЫМИ бросками (второй реестр удачи по ContextParameter не заводим до нужды); стадии босса и реакции NPC через единую точку броска — принято. ## 2026-08-11 — семантика диапазонов дизайн-строк (Todd, в память агента)

Диапазон значения в дизайн-строке аугмента («эффективность 10–45%» при редкости «Необычный – Легендарный») — **лестница значений ПО редкостям** (Необычный 10% / Редкий 25% / Эпический 35% / Легендарный 45%), НЕ диапазон свободного ролла. Ролл копии высчитывается из значения ЕЁ редкости ±25%. Порядок минта: ролл редкости в границах записи → значение лестницы для этой редкости → ±25%. Механики «значение от редкости» в каталоге пока нет — предстоящая работа (новые списки владельца / балансная волна).
