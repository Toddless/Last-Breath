## 2026-09-02 — Библиотека тулинга: контракты по итогам первых ревью (решения ведущего в рамках принятого)

1. **Числа в каноническом писателе сохраняют тип токена**: `Integer` пишется без дробной части, `Float` всегда с десятичной точкой (округление до `FloatDecimals`, хвостовые нули срезаются, минимум одна цифра после точки, `-0.0` → `0.0`). Причина: сериализатор дерева пишет `0.0`/`2.0` через Newtonsoft (1273 строки в `PassiveTree.json`); писатель, схлопывающий `1.0` в `1`, пинал бы файл туда-сюда с игрой и ломал round-trip типа.
2. **Загрузка документа строгая**: дубль ключа, хвост после корня, пустой файл и битый JSON — `FormatException`, никогда не молчаливое «съел»; комментарии JSON не сохраняются (политика канонизирующая).
3. **Ссылка на каталог — объединение**: `[CatalogRef]` разрешён многократно на одном поле, `FieldSchema.RefCatalogs` — список; повод — позиции столов лута и полки торговцев называют id из EquipItems, Resources и Recipes одним полем.
4. **Полиморфизм навешивается на DTO-тип, не на место**: `ISchemaBuilder.Polymorphic(Type, VariantSet)` регистрирует формы записи, и рефлектор применяет их везде, где тип встречается (в том числе внутри вложенных массивов — позиции столов лута лежат в `tiers[].items[]`). Инварианты модели держатся и при `with` (init-гуарды через `field`).
5. **Каталог `Items` — опциональный участник композиции**: `ItemDataProvider` по умолчанию читает общий набор каталогов, `Items` объявляет только Main (у Crafting/LootGeneration фабрика базовых предметов бросает). Побочно вскрыт баг игры: `Items.json` не читается своим DTO, уголь квеста «Поле костей» недостижим — карточка #251.
6. **`BatchEdit` редактора дерева в библиотеку не переносится**: написан против `PassiveNode`, обобщение сломало бы переподключение редактора заменой пространства имён; групповые правки JSON-документа строятся на своих командах.

## 2026-09-02 — Инструменты авторинга: архитектурные развилки (решения Todd) и контракты ведущего

1. **Схема игры — рефлексией из Core через тонкий хост на игру** (вариант А): переиспользуемая часть — библиотека тулинга и шаблон хоста, exe собирается на игру; вариант «один exe + файл схемы» отвергнут, потому что валидаторы, предпросмотр и сухой прогон требуют кода игры в процессе.
2. **Документ редактора — JSON-дерево под схемой** (вариант Б), DTO Core остаются неизменяемыми и служат только валидации и предпросмотру; неизвестные ключи переживают сохранение; порядок ключей при канонической записи — порядок свойств DTO.
3. **Схема — гибрид**: атрибуты на полях DTO (ссылка на каталог, локализуемый ключ, диапазон, вариант полиморфной записи) плюс описатель каталога кодом только для формы файла и полиморфных секций; тест-пин «каждая константа DataCatalog имеет описатель, каждое поле с суффиксом Id имеет ссылку или явный отказ».
4. **Ветвление квестов — модель в игре до редактора квестов** (вариант Б): стадия несёт переходы «на стадию X при условиях», терминальные стадии несут исход, награды привязаны к исходу; контракт данных — отдельным решением перед реализацией.

Контракты ведущего в рамках принятого: описатель параметров условий/действий нарратива — свойство интерфейса фабрики (сверяется тестом через прогон парсера), не атрибут класса. Раскладка `src/Tooling/`: `Tooling.Schema` (атрибуты, модель схемы, интерфейс описателя каталога; без зависимостей — на неё ссылается Core игры), `Tooling.Core` (история правок, JSON-документ и канонический писатель, рефлектор схемы, доступ к .po, поиск, отчёт валидации; без Godot), `Tooling.Ui` (Godot-виджеты, симлинком в хосты по образцу SharedUi), хосты `DataEditor` и `NarrativeEditor`, `Tooling.Tests`. Общие части редактора дерева КОПИРУЮТСЯ в библиотеку, сам редактор дерева не трогается до переподключения.

## 2026-09-01 — Замена иконок: канон и скоуп (решения Todd)

1. **Все иконки, кроме NPC, считаются старыми и заменяются.** Утверждённый эталон — арт зверей (`SharedData/Assets/Npc/Generated/Animals/*_Canon.png`): тушевая линия с плотной штриховкой, краска поверх туши, приглушённая земляная палитра. 97 иконок аугментов сделаны прежней моделью, но **из скоупа замены исключены владельцем**; иконки эффектов (77) — **отдельной волной**, не в этом проходе. Скоуп прохода — 200 иконок: способности 25, оружие 8, броня 57, бижутерия 40, ресурсы крафта 41, ресурсы заточки 26, стойки 3.
2. **Иконка — голый объект на прозрачном, без печёной рамки.** Обрамление и фон рисует слот инвентаря, который уже тонирует рамку по редкости; печёная рамка давала бы двойную (нынешние аугменты именно так и выглядят). Правило касается ОБРАМЛЕНИЯ: рамку-индикатор редкости печь в файл нельзя. Сам объект при этом волен выглядеть на свою редкость — выделка, износ, цвет там, где редкость и есть идентичность предмета (см. п.4).
3. **Старые ассеты якорями не использовать** — «модель создала мусор». Промпт каждой иконки собирается из СМЫСЛА сущности: механика способности из описания, тип и имя предмета, материал ресурса. Технически — текстовая модель `fal-ai/nano-banana`, канон одной константой плюс предметная фраза из таблиц соответствий.
4. **Цвет материала — исключение из обесцвечивания** (по итогам пилота: медная руда пришла неотличимым серым булыжником). У семейств ресурсов собственный цвет материала остаётся единственным насыщенным пятном, всё прочее выцветшее — приём Umbral, где единственный насыщенный цвет лестница редкости. Оговорка распространена и на ресурсы заточки: четыре пыли брони различаются только редкостью, носитель цвета у них — редкость.
5. **Заполняемость кадра нормализуется постобработкой** (решение ведущего, механическое): объект занимает одинаковую долю кадра, иначе меч рядом с рудой вырождается в нитку на 56 px тултипа. Доля — 0.85: на 0.90 крупные силуэты упираются в край и не оставляют места рамке слота.
6. **Канон утверждён владельцем по пилоту** («в целом пойдёт», 2026-09-01) — волны разрешены. Единственная правка: в пыли не должно быть вкраплённых предметов (щитков от `Armor_Dust`), пыль — это помол. Готовая иконка едет в игру заменой png НА МЕСТЕ: соседний `.import` не трогается, он держит uid, а Godot переимпортирует изменившийся файл при скане.
7. **Внутри группы каждый предмет режет свой контур, а не только свой оттенок** (решение ведущего по итогам волны 2). На 64 px — размере иконки в сумке — оттенок слабейший из признаков: восемь тканей на одном силуэте были одной иконкой в восьми тинтах. Правило живёт таблицей `SILHOUETTES` в `build-icon-corpus.ts` и **проверяется сборкой корпуса** (`reportSharedBodies` предупреждает о группе, где на одном теле больше двух записей) — волна считается закрытой, когда её предупреждения погасли. Разводить надо природой предмета (род доспеха, конструкция, край силуэта), а подачей — только когда род уже занят.

## 2026-09-01 — Заточка: вариант «б» (решение Todd, карточка #200)

1. **Заточка достаёт только базовый канал.** `UpdateMultiplier` (+5% за уровень) множит `_baseStats`, оружейную тройку `BaseDamage`/`CriticalChance`/`CriticalDamage` и плоские ИМПЛИСИТЫ. Плоские роллённые аффиксы остаются такими, какими их записал ролл. Причина выбора (разбор `SharpeningAndHitCap.md`): при прежнем правиле аффикс кормился дважды — калибром `PowerMultiplier` и заточкой, — жёсткие капы (резисты 0.75, доп-атака 0.75, блок 0.9) систематически съедали вложенное, а «не точить» не было выгодно ни в одном билде, то есть решения в заточке не существовало.
2. **Возвышение свой охват НЕ меняет** (явная оговорка владельца): ×1.15 по-прежнему поднимает ВСЕ цифровые значения — базовый канал, имплиситы, плоские роллённые строки и однократно значения грантов/properties. Сужается только заточка.
3. **Следствие для документа**: колонки «(б) +возвышение» в `SharpeningAndHitCap.md` §1 посчитаны в предположении, что возвышение тоже сузится, и НЕ описывают принятый вариант. Верные числа на +12 и возвышении: меч — физ 577.3, добавленный огонь 258.75, крит-урон 3.43275; `Body_Stoneheart` — здоровье 717.6, огнерезист 0.1725. Колонки «+12» без возвышения совпадают с принятым вариантом и остаются верными.
4. **Два условия, без которых вариант не поедет** (из того же разбора, оба — данные, числа за владельцем): бижутерии вернуть вес базы (её база — 7.5 атрибута и 0.03 шанса, +60% от этого не читается как четыре руны), и бюджет доп-атаки перенести из семейных суффиксов в `baseStats`, иначе правило «кап только с заточкой» лишается носителя.

3. **Инвариант «редкость — авторское слово, не хранится» отменён сознательно**: роллённая редкость живёт на `AugmentInstance` и сейвится; легаси-копии без редкости **перекатываются один раз при загрузке** в диапазоне своей записи. Семантика дропа: группа таблицы выбирает запись по покрытию диапазоном и ФИКСИРУЕТ редкость группы (таблица — владелец того, что падает); вне таблиц (конверсия, торговец) копия роллит по диапазону записи — распределения расходятся, это принято (как у экипировки).
