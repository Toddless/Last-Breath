# Dual-grid тайлсет: суть техники и план реализации

Источник: «Draw fewer tiles — by using a Dual-Grid system!» (jess::codes, техника Оскара Столберга) + её референс-реализация для Godot. План адаптирован под наш стек: Godot 4.7, `TileMapLayer`, стиль C, базовый грунт `SharedData/Assets/Tiles/Forest_Ground_Base.png`.

## 1. Суть техники

**Проблема классического автотайлинга.** Стандартный блоб-автотайл рисует границы террейна ПО ЦЕНТРУ клетки и требует 47 тайлов (полный набор соседств из 256 конфигураций после дедупа); 15-тайловый упрощённый набор даёт кривые стыки, а одинаково скруглить внутренние и внешние углы почти невозможно. Каждый новый террейн или анимация умножает объём арта (пример из видео: 11-кадровая анимация воды — 507 тайлов классикой против 155 на dual-grid).

**Решение.** Две сетки:
- **Мировая (данные)** — невидимая; каждая клетка хранит только «какой террейн» (для пары террейнов — бит).
- **Дисплейная (визуал)** — сдвинута на **полклетки** по X и Y; каждый её тайл накрывает **углы четырёх** мировых клеток.

Дисплейный тайл выбирается по состоянию своих четырёх углов: 2⁴ = **16 конфигураций → 16 тайлов** на пару террейнов (при симметричном арте — до 6). Границы при этом проходят между мировыми клетками — стыки бесшовные, углы скруглены одинаково, геймплейная сетка (проходимость, клики) остаётся честной мировой и не знает о визуале.

**Цена.** Набор тайлов — на ПАРУ террейнов (трава↔грязь, трава↔вода...): N взаимно граничащих террейнов = попарные наборы или слоёная композиция «каждый террейн поверх базы». Для нашего мира со слоями-подложками это штатный путь: базовый грунт всегда снизу, каждый следующий террейн — свой dual-grid-слой с прозрачностью.

## 2. Архитектура у нас (Godot 4.7)

Компонент `DualGridTerrainLayer` (Node2D, C#), инкапсулирует пару слоёв:

- `_world : TileMapLayer` — данные, невидимый (или вообще словарь `Vector2I → bool`, если мировая сетка уже есть у другого владельца); клетка = «террейн присутствует».
- `_display : TileMapLayer` — визуал, `Position = _world.Position - tileSize / 2` (сдвиг на полклетки вверх-влево, отсчитывается от мирового слоя); заполняется только кодом. Знак задан конвенцией масок: дисплейный тайл (x, y) накрывает углы мировых клеток (x−1, y−1), (x, y−1), (x−1, y), (x, y), значит его центр обязан лечь на общую точку этой четвёрки.
- **Таблица 16 правил**: битовая маска четырёх углов (TL, TR, BL, BR — мировые клетки, которые накрывает дисплейный тайл) → атлас-координата в тайлсете. Единственная точка правды — DualGridAtlas; раскладка выбирается отдельно для каждого террейна.
- `SetCell(coords, present)` / `FillRect` / `Clear`: правка мировой клетки инвалидирует ровно **четыре** дисплейных тайла, которые её накрывают, — точечный пересчёт, без полного скана.
- Загрузка карты: один проход по мировым данным → массовое заполнение дисплея.

C#-компоненты работают в игре без `[Tool]`. Редакторное превью выполняет отдельный GDScript-плагин (§7); свойство Visible мирового слоя он не меняет.

Интеграция: MainWorld держит базовый грунт обычным `TileMapLayer` с `Forest_Ground_Base` (фон, без автотайлинга — он бесшовный сам по себе), а каждый «накладной» террейн — своим `DualGridTerrainLayer`. Шейдер/шум поверх базы живёт на слое базы и dual-grid не трогает.

Редактирование уровня: на первом этапе — правка мировых данных кодом/инспектором; полноценная кисть в редакторе Godot (TileMap-плагин) — отдельный этап, если понадобится (мировой слой можно рисовать штатной кистью Godot по невидимому TileMapLayer — компонент подхватит его содержимое на `_Ready` и на сигнале изменений).

## 3. Арт-конвейер 16-тайлового листа (nano banana)

Тайл границы = переход «террейн A ↦ террейн B» в одном из 16 угловых сочетаний. План генерации:

1. Базовые текстуры обоих террейнов уже бесшовные (конвейер тайлов: жёсткая бесшовность в промпте + контроль замосткой 2×2).
2. Генерируем **один лист переходов**: якорь — обе базовые текстуры, промпт — «4×4 атлас переходов травы в грязь, границы через середины тайлов, рваная органическая кромка в стиле штриховки»; при нестабильности — генерируем 3–4 ключевых тайла (прямая кромка, внешний угол, внутренний угол, диагональ) и добираем остальные поворотами/отражениями в ImageMagick (симметричный набор ≈ 6 уникальных).
3. Контроль: собрать тестовую карту-шахматку скриптом и посмотреть глазами все 16 стыков.
4. Атлас содержит 4×4 тайла. Поле AtlasLayout у TerrainEntry выбирает RowMajor (старые листы, маски 0–15 по строкам) или Grouped (авторская раскладка ниже). Новый лист подключается с соответствующей настройкой.

## 4. Этапы реализации

| # | Этап | Скоуп |
|---|---|---|
| 1 | Ядро | `DualGridTerrainLayer` (Core-логика таблицы масок — чистый C#, тестируемо; Godot-обвязка тонкая), тестовая сцена-песочница, набор-заглушка 16 тайлов (контрастные цвета) для проверки правил |
| 2 | Арт | Лист переходов «лесной грунт ↦ тропа/грязь» конвейером §3, замена заглушки |
| 3 | Мир | Слой в MainWorld поверх базового грунта; правка данных — кистью по невидимому мировому слою |
| 4 | Позже | Второй террейн (вода?), анимированные переходы (16 кадровых наборов), кисть-плагин если штатной не хватит |

Пины этапа 1 (Godot-free): таблица 16 масок тотальна и уникальна; правка клетки инвалидирует ровно 4 дисплейных адреса; преобразование координат мир↔дисплей обратимо, включая отрицательные координаты (известная ловушка реализации из видео).

## 5. Решения (владелец, 2026-08-28)

1. Первая пара террейнов: **лесной грунт (`Forest_Ground_Base`) ↦ тропа/грязь**.
2. Размер клетки: **128×128** (персонаж ~150 px видимого тела при кадре 480² × 0.35 — клетка ≈ корпус; база 1024² режется на 8×8 разных тайлов подложки против «маяков» повторения; атлас переходов 4×4 = 512×512; при нужде в более тонких изгибах — переезд на 64 тем же макетом атласа).
3. Владелец мировых данных: **невидимый `TileMapLayer`** на сцене (2026-08-28: слои живут детьми контейнера, см. §6), рисуется штатной кистью Godot; компонент читает его на `_Ready` и по сигналу изменений. Сигнал `changed` координат не несёт и срабатывает на каждый шаг кисти, поэтому пересчёт откладывается до конца кадра и сверяет снапшот `get_used_cells` с предыдущим — на дисплей уходит только дельта. Раскладку можно проверять превью в редакторе (§7) и запуском сцены.

## 6. Контейнер террейнов (`TerrainRoot`, 2026-08-28)

Каждый террейн больше не отдельная сцена с ручной обвязкой экспортов. В локации стоит один `TerrainRoot` (Node2D, `z_index = -1`, y-sort ВЫКЛ), его дети — невидимые слои данных, по одному на террейн, имя ребёнка = ключ записи конфига (`Dirt`, `Turf`, `Water`, `TallGrass`). Владелец рисует штатной кистью по этим слоям; их тайлсет (кисть) контейнер не трогает — только читает клетки.

Конфиг — ресурс `TerrainRootConfig` (список `TerrainEntry`: имя слоя, лист переходов 4×4, опциональные материал поверхности и скаттер), готовый экземпляр леса — `World/ForestTerrains.tres`. На `_Ready` контейнер для каждого названного слоя собирает тайлсет из листа переходов кодом, создаёт дисплейный слой с материалом записи, вешает `DualGridTerrainLayer` на пару и `PropScatterLayer`, если у записи есть текстура пропа. Материал назначается только сгенерированному дисплейному слою: невидимый слой данных остаётся чистой кистью и не участвует в отрисовке. **Порядок отрисовки = порядок детей.** Пропы родятся не под контейнером (он под землёй), а в узле `_propContainer` — по умолчанию родитель контейнера, то есть y-sort-пул персонажей.

Конвенция проверяется вслух: слой без записи, запись без слоя, повтор имени, запись без имени — каждый случай уходит в Tracker и в консоль. Чистая часть проверки — `Core/World/DualGrid/TerrainRoster`, она под тестами.

Новый (пятый) террейн: пустой `TileMapLayer`-ребёнок контейнера с кистевым тайлсетом → имя по ключу → запись в `.tres` (имя + лист переходов). Кода не трогаем.

`ForestTerrains.tres` назначает земле `World/Shaders/TerrainBreakup.tres` только для подавления повторяемости рисунка. Переход принадлежит верхнему `TurfDisplay`: его отдельный `TerrainEdgeBlend.tres` расширяет alpha травяного атласа в поле плотности, переносит цвет ближайших непрозрачных пикселей наружу и прореживает его мелким мировым шумом. Нижний `DirtDisplay` шейдер не читает и не перерисовывает — стандартная alpha-композиция CanvasItem сама даёт полосу `земля → редкие островки травы → плотная трава` между разными TileMapLayer. Полностью заполненный тайл маски `1111` остаётся исходным. Выборки зажаты в пределах текущей ячейки атласа 4×4, поэтому соседние варианты перехода не протекают друг в друга. Ширина, смещение наружу и прореживание настраиваются только в `TerrainEdgeBlend.tres`, без дублирования материала в сцене.

## 7. Превью в редакторе (2026-09-08)

Плагин **Dual Grid Preview** включён в основном проекте. Кнопка **Terrain preview** в панели 2D переключает готовые текстуры и исходные дебаг-тайлы. Флаг **PreviewInEditor** у TerrainRoot отключает превью только этого контейнера. При первом подключении плагина к уже открытому редактору его можно включить в Project Settings → Plugins или переоткрыть проект.

Превью обновляется каждые 0,1 секунды: рисование, стирание, undo/redo, смена конфигурации, Transitions, AtlasLayout и SurfaceMaterial. Изменение присутствия одной клетки пересчитывает четыре дисплейные клетки. Полная пересборка требуется при смене атласа, размера тайла или раскладки. Порядок слоёв и сдвиг на полклетки совпадают с рантаймом. Скаттер пропов этим плагином не показывается.

### Ограничение C# unload

С 2026-09-01 `[Tool]` отключён у TerrainRoot, DualGridTerrainLayer и PropScatterLayer из-за удержания сборки при editor reload (godotengine/godot#78513). Включать атрибуты обратно ради превью не нужно. EditorReloadUnhook очищает managed-подписки при выгрузке, но сам по себе не решает удержание живых tool-объектов.

Новый плагин — GDScript EditorPlugin. Он читает экспортированные свойства C# placeholder-ресурсов, не вызывает C#-методы и не создаёт C# tool-узлов. Между обновлениями хранятся только native TileMapLayer, числовые instance id и снимки клеток; C#-ресурсы и managed Callable в кэш и подписки не попадают. Таблица масок редакторной проекции повторяет контракт DualGridAtlas, обе раскладки проверяются тестом.

### Сохранение и очистка

- Дисплейные слои — internal-узлы без Owner и скрипта, без коллизий и навигации. В PackedScene они не сохраняются.
- Дебаг-слой скрывается через RenderingServer по canvas RID. Его Visible, тайлсет, клетки и undo-история не изменяются. При отключении плагина или превью восстанавливается отображение согласно текущему Visible.
- Смена вкладки, удаление слоя и отключение превью удаляют сгенерированные слои. Повторное обновление не создаёт дублей.

### Проверка

Редакторный тест: Godot `--headless --editor --path src/Main --script res://Addons/DualGridPreview/tests/preview_test.gd --quit-after 20`. Требуется собранный C#-проект. Проверяются чтение реальных placeholder-ресурсов, все 16 масок обеих раскладок, добавление и стирание клеток, смена атласа, отсутствие preview-узлов в PackedScene, отключение, удаление слоя и очистка при смене сцены. Успех обозначается строкой `DUAL_GRID_PREVIEW_TEST` с нулём failures; отдельно следует смотреть ошибки Godot в журнале.
## 8. Авторская раскладка атласа (2026-09-08)

У записи террейна настройка `AtlasLayout`: `RowMajor` (0, значение по умолчанию для существующих листов) или `Grouped` (1). У самостоятельного `DualGridTerrainLayer` есть такая же настройка. Контейнер передаёт её сгенерированному слою.

`Grouped` — номера масок слева направо, сверху вниз:

```text
 1   2   8   4
 3  10   9   6
12   5   7  11
13  14   0  15
```

Биты углов остаются TL=1, TR=2, BL=4, BR=8. Меняются только координаты выбора изображения. Пустая маска стирает дисплейную клетку. Полный тайл в обеих раскладках остаётся в (3,3), поэтому материалы, использующие эту координату, совместимы.

Листы Dirt_Transitions, Square_Tiles_Transitions и Stone_Road_Transitions используют Grouped. Эта настройка включена для Dirt в ForestTerrains и для Dirt/Square в конфигурации SourceOfPowerNearVillage. Старые Forest_GrassTo* используют RowMajor.

Мировой слой хранит присутствие террейна: любой нарисованный тайл считается заполненной клеткой, даже тайл с номером 0. Для отсутствия террейна клетку нужно стереть. Номера и формы кистевых дебаг-тайлов не управляют дисплейными краями; при рисовании удобно использовать полный тайл 15.
