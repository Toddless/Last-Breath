# Расширение крафта — обсуждение решений

> [!note] Статус
> Рабочий документ от 2026-09-17 по концепту «Расширение крафта — теги модификаторов». Согласованные правила находятся в конце документа. Пустые поля «Ответ / решение» предназначены для следующих уточнений. Предложения не являются принятыми правилами и не означают начало реализации.

## Обзор

Игрок управляет пулом аффиксов опциональными ресурсами: меняет веса по тегам и исключает группы кандидатов. Первоначальный крафт сохраняет основу будущих перековок; текущая перековка влияет на одну операцию и пополняет историю затрат для разбора.

## Риски

- Повторное применение сохранённых влияний при каждой перековке приведёт к непредусмотренному постоянному росту весов.
- Если использовать накопленный список ресурсов разбора для восстановления пула, каждая перековка начнёт менять будущие результаты.
- Групповой тег может несколько раз усилить один композит из-за совпадения с несколькими частями.
- Объединение строк с разными диапазонами, условиями или тегами может потерять различия кандидатов и дать неверные веса.
- Сильное сужение пула может оставить кандидатов только для одной семьи аффиксов или меньше нужного числа уникальных строк.
- Числовая реализация без контроля конечности может переполниться при больших количествах ресурсов. Отсутствие игрового потолка не делает NaN или бесконечность допустимыми весами.
- Цвет изменения веса и словесная вероятность могут восприниматься как одно и то же: вес строки вырос, но другие выросли ещё сильнее.
- Сохранённые пулы увеличивают размер сейва и требуют явного решения о применении будущих правок каталогов к старым предметам.

## Критерии успеха

- По выбранным ресурсам понятно, какие строки исключены, усилены и ослаблены.
- При повторном открытии окна и загрузке сохранения сохраняется основа первоначального крафта.
- Повторные перековки не накапливают временные усиления, но затраченные ресурсы учитываются при разборе.
- Увеличение количества одинакового ресурса меняет влияние согласно одной воспроизводимой формуле.
- Предварительный просмотр совпадает с фактическим списком доступных кандидатов.
- Пустой пул отклоняет операцию без оплаты, единственный кандидат допускает гарантированный результат.

## Требования

### Обязательно

- Строго типизированный enum тегов и явная карта групп по аналогии с агрегатами EntityParameter.
- Теги у условного и безусловного варианта одной характеристики совпадают; конверсия имеет оба тега.
- Композит исключается целиком при совпадении с запретом.
- Источники влияния первой итерации — только опциональные ресурсы; количества учитываются.
- Раздельно хранить пул создания и затраты для разбора; перековка не изменяет сохранённый пул.
- Не применять управление тегами к отдельному слоту поведенческих эффектов.
- Сохранять ограничения аффиксов и идентичностей строк, а также строки без тегов.
- Запрет имеет приоритет над любым увеличением веса.

### Желательно

- Показывать причину исключения и вклад выбранных ресурсов, сохраняя компактный основной интерфейс.
- Проверять разметку и ссылки на enum-теги в инструментах данных до запуска игры.
- Иметь диагностический просмотр точных весов для проверки баланса, отдельно от приблизительных шансов игрока.

### Возможно позднее

- Применение механизма к другим операциям, если для них будет отдельно согласован дизайн.
- Другие источники изменения весов. Экипировка, мастерство и пассивки пока не входят в источники этой системы.

## Идеи и последствия для текущей системы

### Пул и история затрат — разные данные

Текущая перековка собирает основу через `GetLiveRerollPool` из каталога предмета и ID материалов создания. Целевой вариант берёт сохранённый снимок, созданный один раз. Текущие добавки работают с копией этого снимка.

Сейчас `UsedRequiredResources` и `UsedOptionalResources` служат и источником исходных материалов, и основой возврата при разборе. Добавлять туда расходы перековки без изменения этих ролей нельзя: текущая сборка пула примет их за постоянные источники модификаторов. Нужен отдельный учёт затрат перековки либо другая явно разделённая модель.

Предлагается сохранять в снимке описания кандидатов, их итоговые веса и сведения об исключении для UI. Не сохранять как постоянные удаления временные фильтры занятых строк и семьи выбранной цели перековки. Нужно отдельно выбрать глубину снимка: только веса или также диапазоны, теги и состав записи.

### Формула внутри одной операции

Согласованная основа: `W = B × (1 + Σ(quantity × delta))` для всех совпавших эффектов изменения веса; явный запрет исключает кандидата независимо от результата формулы. Для неположительного результата предлагается ограничение снизу нулём, что требует отдельного ответа T03.

Здесь `B` при создании — исходный вес, при перековке — сохранённый вес. `delta = 1` означает +100%, `delta = -0.5` — снижение на 50%. Верхнего игрового ограничения нет. Нижняя граница ноль — предложение для корректного случайного выбора, а не согласованный способ трактовать отрицательные веса.

Два ресурса +100% внутри одной операции дают 50 → 150. Один такой ресурс при создании даёт сохранённые 100, ещё один при перековке — временные 200. Последующая попытка без него использует снова 100. Оба примера согласованы.

### Группы тегов

`Elemental` объединяет Fire/Cold/Lightning, `Defence` — Evade/Armor/Barrier. Карта групп отдельна от карты характеристик: текущее `AllDefence` включает только Evade/Armor.

Каждый эффект ресурса сопоставляется со всем модификатором один раз. Запрет Elemental срабатывает по любому члену, а повышение Elemental не применяется дважды к композиту Fire + Cold. Отдельные эффекты Fire и Elemental складываются. Количество ресурсов усиливает вклад эффекта, но число совпавших частей композита его не умножает.

Идентичность строки для запрета дублей не должна зависеть от набора тегов. Разметка не создаёт новый слот для того же модификатора. При объединении весов следует отличать совпадающую запись кандидата от одного и того же параметра с разными диапазонами или условиями.

## Зафиксированные решения

| ID | Решение |
| --- | --- |
| A01 | Операции по тегам: исключение из выпадения и увеличение/уменьшение веса. Защита существующего аффикса не входит в скоуп. |
| A02 | Теги — enum со строгой типизацией; Elemental = Fire/Cold/Lightning, Defence = Evade/Armor/Barrier. Исходный перечень также содержит Physical, Critical, Speed, Mana, Health, Resistance. |
| A03 | Конверсия имеет оба тега. Условные и безусловные варианты одного бонуса имеют одинаковые теги. |
| A04 | Поведенческие эффекты отдельного слота не участвуют в системе тегов модификаторов. |
| A05 | Композит неделим: совпадение с запрещённым тегом исключает всю строку. |
| A06 | Источники влияния — только опциональные ресурсы. Увеличение количества одинакового ресурса усиливает влияние; веса одинаковых модификаторов складываются. |
| A07 | Влияния одного тега складываются, допускаются повышения и снижения без верхнего игрового предела. Запрет абсолютен. |
| A08 | Первая итерация — создание и перековка аффиксов. |
| A09 | При создании фиксируется пул с результатами всех первоначальных влияний. Пример сохранённого веса: 50 × 2 = 100. |
| A10 | Добавка перековки действует на сохранённую основу только для текущей операции: 100 × 2 = 200. Сохранённый вес остаётся 100. |
| A11 | Перековка сохраняет ID и количества использованных ресурсов для частичного возврата при разборе, но не мутирует сохранённый пул. |
| A12 | Существующее поведение вкладов одинаковых модификаторов из разных источников сохраняется; запрет дублей аффиксов не отменяется. |
| A13 | Пустой допустимый пул отклоняет операцию. Сужение до единственного нужного кандидата допустимо. |
| A14 | Игрок видит теги и приблизительные шансы. Исключённые строки зачёркнуты/серые, усиленные зелёные, ослабленные оранжевые/красные. |
| A15 | Допускаются строки без тегов, включая атрибуты. Прямое влияние по тегам к ним неприменимо; косвенное изменение вероятности из-за других весов возможно. |
| A16 | Внутри одной операции складываются процентные прибавки: два экземпляра +100% дают ×3, а не ×4. |
| A17 | Влияния конкретного и группового тегов складываются. Каждый отдельный эффект ресурса применяется один раз на строку, независимо от числа совпавших тегов/частей. |
