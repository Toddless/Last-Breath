## §1. Инвентаризация и правила счёта

### 1.1. Слоты экипировки

`EquipmentPiece` (`src\Core\Enums\EquipmentPiece.cs`) — **10 надеваемых слотов одновременно**:

`Body, Belt, Gloves, Boots, Helmet, Amulet, Cloak, Weapon, Ring, Ring2`

`Ring2` — только слот «вторая рука» кукольного экрана; сам предмет всегда `Ring`. Оружие одно (офф-хенда/щита в перечислении нет). Файлов баз девять — `Ring.json` покрывает оба кольцевых слота.

Базовых пулов модификаторов тоже девять: `Amulet, Belt, Body, Boots, Cloak, Gloves, Helmet, Ring, Weapon`. Остальные ~70 пулов в `EquipItemModifierPools.json` — именные (уникальные) предметы по 2–4 записи, в общий счёт не идут.

### 1.2. Сколько строк несёт предмет

`AffixRules.SlotsFor` (`src\Core\Modifiers\AffixRules.cs`) — это **единственный** источник ёмкости:

| Редкость | Префиксы | Суффиксы | Всего строк |
| --- | --- | --- | --- |
| Common | 0 | 0 | 0 |
| Uncommon | 1 или 0 | 0 или 1 | 1 |
| Rare | 1 | 1 | 2 |
| Epic | 2/1 или 1/2 (50/50) | | 3 |
| Legendary | 2 | 2 | 4 |
| Mythic | — авторский шаблон, в ролл аффиксов не входит | | 4 (унаследованы от легендарки) + подарок |

Дубли контролирует `LineIdentity`: идентичность строки = параметр + **тип значения** + канал + условие. Значит `FireDamage flat` и `FireDamage inc` — **разные** строки, один предмет может нести обе. Это существенно для колец и оружия.

### 1.3. Заточка и возвышение — ФАКТ ПО КОДУ

```
// src/Core/Items/EquipItem.cs
private const float UpgradeBonusPerLevel = 0.05f;      // +5% за уровень
UpdateMultiplier += appliedLevels * UpgradeBonusPerLevel;   // ЛИНЕЙНО, не сложным процентом
protected float LineMultiplier => UpdateMultiplier * AscensionMultiplier;

private float Scaled(float baseValue, ModifierValueType type) =>
    type == ModifierValueType.Flat ? baseValue * LineMultiplier : baseValue;
```

* `maxUpdateLevel` = **12** во всех базах (`EquipItems\*.json`), т.е. предельная заточка даёт ×1.60.
* Возвышение: `item.AscensionMultiplier = 1f + mastery.AscensionStatBonus`, а `ascensionStatBonus: 0.15` в `SharedData\CraftingMastery\CraftingMastery.json` → **×1.15**. Подтверждено.
* `CanAscend` требует `Rarity == Legendary && UpdateLevel >= MaxUpdateLevel`. **Мифик по определению — легендарка на +12, затем ×1.15.** Итоговый множитель строки мифика = `1.60 × 1.15 = 1.84`. Возвышение запечатывает предмет (`IsSealed`), дальше он неизменен.
* Подарок возвышения (`ItemAscender.TryRollGift`) — вероятностный (`mythicGiftBaseChance: 0.15` × мастерство). Может быть либо лишняя строка из `MythicModifiers.json`, либо операция «+N уровней заточки» (поднимает `MaxUpdateLevel` и дотачивает). В базовый счёт **не включён** — см. §2, допущение Д7.

> **РАСХОЖДЕНИЕ С ЗАДАНИЕМ №1 (важное).** В задании: «+5% за уровень заточки на ВСЕ модификаторы; возвышение ×1.15 на всё». Код применяет `LineMultiplier` **только к строкам типа `Flat`**. Строки `Increase`, `Multiplicative` и `Flag` заточка и возвышение не трогают вообще — в комментарии это заявлено намеренно: «A percent line already multiplies a value the scales have raised, so scaling it too would stack a multiplier on a multiplier». По инструкции считаю **по коду**. Практически это почти не меняет итог, потому что в пулах экипировки процентных строк всего девять штук (см. 1.5) и все они локальные, т.е. умножают уже отмасштабированный плоский ролл того же предмета.

### 1.4. Редкость НЕ масштабирует значения

Ни в `ItemCreationService`, ни в `EquipItemMinter` нет множителя от редкости. Единственные множители значений:

* `PowerMultiplier` = `1 + ItemModifierMultiplier × TotalDifficultyMultiplier` (`LootGenerationService.cs:267`), где `itemModifierMultiplier: 0.10` — это **сложность убийства**, не редкость;
* `rarityMultipliers` из `LootConfiguration.json` (`Rare 1.15 / Epic 1.3 / Legendary 1.45 / Mythic 4`) используется **только в оценщике цены** — `Core\Trade\ItemValuation.cs:36`.

> **СНЯТО (Todd, 2026-08-25).** Никакого «расхождения» нет: лестница по редкостям — конвенция дизайн-строк АУГМЕНТОВ и на пулы экипировки никогда не распространялась. Для экипировки так и задумано: `{ "min": 0.1, "max": 0.45 }` — свободный ролл, одинаковый для всех редкостей; редкость меняет только **количество** строк (2/3/4). Расчёты §3 по коду — верны как есть. Вопрос В1 в §6 закрыт этим же ответом.

### 1.5. Локальный шов — меняет смысл процентных строк

```
// src/Core/Items/EquipItem.cs
protected float ResolvedLocalFlat(EntityParameter parameter) {
    (float flat, float increase, float multiplier) = LocalBucket(parameter);
    return flat * (1f + increase) * (1f + multiplier);
}
// BuildResolvedModifiers: наружу уходят только Scope == Global + свёрнутый локальный Flat
```

* Локальная **плоская** строка наружу уходит (свёрнутая со своими локальными процентами).
* Локальная **процентная** строка наружу не уходит **никогда**. Она умножает только собственный плоский канал того же предмета по тому же параметру.

Следствие: `FireDamage inc 0.15..0.55` на кольце — это **не** «+35% огненного урона персонажу». Это +35% к тем ~125 огня, что несёт само это кольцо. Если на кольце нет плоского огня, процент не делает ничего.

**Все девять процентных строк в пулах экипировки — локальные:**

| Строка | Слоты | Диапазон |
| --- | --- | --- |
| `PhysicalDamage inc` | Weapon | 0.25–0.65 |
| `FireDamage inc` | Weapon / Amulet / Ring | 0.25–0.70 / 0.10–0.45 / 0.15–0.55 |
| `ColdDamage inc` | Weapon / Amulet / Ring | те же |
| `LightningDamage inc` | Weapon / Amulet / Ring | те же |
| `CriticalChance inc` | Weapon | 0.15–0.45 |

### 1.6. Что НЕ достижимо на экипировке вообще

Это главный вывод инвентаризации и он же — мандат дерева.

**Ни на одном слоте нет глобальной строки `Increase` для:**
`Health`, `Armor`, `Evade`, `Barrier`, `Mana`, `HealthRecovery`, `ManaRecovery`, `BarrierRecovery`, `SpellDamage`, `MulticastChance`, `AdditionalHitChance`, `Accuracy`, `Suppress`, `SuppressChance`, `BlockChance`, `ArmorPenetration`, `PoisonDamage`, `BleedDamage`, `BurningDamage`, а также глобального `PhysicalDamage`/элементального `Increase`.

**Грамматика системы:** экипировка даёт **плоский пул и базы**; дерево даёт **проценты, которые этот пул умножают**. Они не конкуренты, они множители друг друга. Это же объясняет, почему по чистым лучам дерева малые ноды почти сплошь `Increase`.

Отдельно по фокусам:

* **Сила.** Броня — только плоская (базы + аффиксы). `ArmorPenetration` на экипировке отсутствует полностью. `BurningDamageMultiplier` есть **только префиксом амулета** (0.05–0.15).
* **Ловкость.** Уклонение — только плоское. **Яд и Кровотечение представлены на экипировке одной-единственной позицией: префикс амулета `PoisonDamageMultiplier` / `BleedDamageMultiplier` / `AllDoTDamageMultiplier`, 0.05–0.15.** Причём по конвенции слэша это **один** модификатор на выбор, и он занимает префикс амулета, конкурируя с точностью и элементальным уроном. Потолок ДоТ-билда со шмота — ~0.18 мультипликатора на мифике. Всё остальное обязано прийти из дерева.
* **Интеллект.** `SpellDamage` — только плоский (Weapon 50–180, Gloves 60–110), процента нет нигде. `MulticastChance` — только плоский 0.01–0.07 (Weapon, Ring). `Barrier` — только плоский. `BarrierRecovery` **не встречается ни в одном пуле и ни в одной ноде дерева** — параметр реализован в коде и пуст в данных.

## §2. Допущения

Каждое допущение помечено; все они — мои, не владельца.

**Д1. Состав мид-набора.** Владелец назвал «редкими +3, эпическими +6, легендарными +3, +6, +12» — пять категорий на десять слотов. Предлагаю раскладку и считаю по ней:

| Слот | Редкость | Заточка | Строк (P/S) | Множитель плоских |
| --- | --- | --- | --- | --- |
| Weapon | Legendary | +12 | 2/2 | 1.60 |
| Amulet | Legendary | +6 | 2/2 | 1.30 |
| Body | Legendary | +3 | 2/2 | 1.15 |
| Ring1 | Legendary | +3 | 2/2 | 1.15 |
| Helmet | Epic | +6 | 2/1 | 1.30 |
| Belt | Epic | +6 | 2/1 | 1.30 |
| Ring2 | Epic | +6 | 2/1 | 1.30 |
| Gloves | Rare | +3 | 1/1 | 1.15 |
| Boots | Rare | +3 | 1/1 | 1.15 |
| Cloak | Rare | +3 | 1/1 | 1.15 |

Логика: 3 редких + 3 эпических + 4 легендарных, из них ровно по одной на +6 и +12 — «оружие доведено, остальное подтягивается». Ёмкость мид-набора = **31 строка**, суммарный «вес строк» (Σ строк × множитель) = **39.4**.

**Д2. Состав лейт-набора.** Все 10 слотов мифические: 4 строки, множитель плоских **1.84**. Ёмкость = **40 строк**, вес = **73.6**. Отношение лейт/мид по весу = **×1.87**.

**Д3. Epic-раскладка.** `AffixRules` кидает 2/1 или 1/2 с шансом 50/50. Беру **2 префикса + 1 суффикс** — префиксы в этих пулах несут наступательные и ёмкостные строки, целевой билд будет их фармить. Для суффиксных фокусов (крит, подавление, атрибуты) это допущение занижает результат.

**Д4. Средний ролл.** Беру середину диапазона `(min+max)/2`. Роллы независимы и не отбираются.

**Д5. `PowerMultiplier` = 1.0.** То есть предметы, взятые с нулевой сложности. Реально `1 + 0.10 × TotalDifficultyMultiplier`, и это **общий линейный множитель на все плоские значения**. Все числа §3 умножаются на него как есть.

**Д6. Идеальный таргетинг.** Считаю, что каждая вещь несёт лучшие доступные строки своего фокуса из пула своего слота. Это верхняя граница — реальный лут роллит по весам.

**Д7. Подарок возвышения исключён.** Вероятностный и «либо строка, либо уровни». Апсайд, не база.

**Д8. Базы предметов взяты как средние по архетипам.** В `EquipItems\*.json` 68 предметов несут `baseStats`. Билд подбирает архетип под фокус (броневые базы для Силы, уклоненческие для Ловкости, барьерные для Интеллекта). Беру среднее из средних по параметру. **Плащ несёт только базу уклонения** — броневого плаща в данных нет, для силового билда это мёртвый слот по базе.

**Д9. Одна редкая/эпическая вещь не может нести больше строк, чем есть подходящих в её пуле.** Там, где у фокуса меньше кандидатов, чем слотов, слот остаётся пустым — это отражено в «использовано строк».

### 3.4. Сводка «что растёт от мид к лейту»

Вес строк растёт ×1.87 (Д1/Д2). Разброс по конкретным строкам (×1.15 … ×6.4) объясняется не мификом как таковым, а тем, сколько **дополнительных слотов** параметр получает, когда редкие и эпические вещи становятся четырёхстрочными. Строки, которые уже стояли на всех подходящих слотах в миде (Accuracy у Силы, ×1.15), растут ровно на множитель заточки; строки, которым в миде не хватало слотов (Suppress, AllAttribute, сопротивления), растут кратно.

## §4. Дерево против шмота

### 4.1. Сколько дерево вообще может дать

Бюджет 65 очков (док владельца: 50 за уровни мастерства + 15 за «Испытания сильных»). По его же ожидаемой раскладке: 8–10 способностей, 5–6 сокетов Т2, 3–4 сокета Т3, **~35–40 очков на проходные и малые ноды**. То есть на статы работает чуть больше половины бюджета, и часть этого уходит в проходные ноды с атрибутами.

Авторская ветка Силы — 8 кластеров, 48 нод суммарно. На ~37–40 очков берётся **шесть** из восьми. Возьмём типичный силовой набор (кластеры 1, 2, 3, 5, 6, 7 = 37 нод):

`+65% физ.урон, +15% пробитие брони, +38% здоровье, +59% восстановление здоровья, +125 к восстановлению, +45% броня, +35% огненный урон, +45% мультипликатор горения`

### 4.2. Прямое сопоставление, лейт-гейм

| --- | --- | --- | --- | --- |
| Броня | 6 402 плоско | +45% | +2 881 | **45%** |
| Здоровье | 1 638 аффиксы (+базы, если броневые архетипы — 2 174) | +38% | +622 / +1 448 | **38%** |
| Восстановление здоровья | 327 плоско | +59% и +125 плоско | +318 | **97%** |
| Физический урон | 612 аффиксы + 405 база оружия | +65% | +661 | **65%** |
| Огненный урон | 832 плоско | +35% | +291 | **35%** |

### 4.3. Вывод

**Дерево и шмот — не соперники, а два множителя одного произведения.** Шмот определяет размер пула, дерево — коэффициент. По «толстым» параметрам (броня, уклонение, здоровье, элементальный урон) дерево добавляет **35–65%** поверх шмота — заметно, но шмот остаётся ведущим. По параметрам, которых на экипировке нет вовсе (пробитие брони, мультипликаторы ДоТ, проценты восстановлений, `SpellDamage`, `MulticastChance`, `BarrierRecovery`), дерево — **единственный** источник, и там его доля 100% и выше.

Это даёт естественный критерий для новых кластеров, которым я и пользуюсь в §5.

### 4.4. Целевая доля кластера — объявляю явно

**Правило Ц1.** Кластер гибридного клина, тратящий 4–6 очков, должен добавлять по своему головному параметру **25–40% от лейт-бюджета экипировки** по этому же параметру.

**Правило Ц2.** Для параметров, которых на экипировке нет, ориентир не «доля шмота», а авторские чистые кластеры: гибридный кластер даёт **75–85%** от сопоставимого кластера чистого луча. Клин — крюк в сторону, он обязан быть настоящим выбором, но не должен обгонять специализацию.

**Правило Ц3 (санитарное).** Внутри одного клина сумма всех кластеров по одному параметру не должна превышать то, что даёт этот же параметр на чистом луче. Иначе «зайти в клин» станет выгоднее, чем расти по лучу. *Замечание: авторская пара «Ловкость+Сила» уже близка к этой границе — кластер «Физ. Урон + Урон кровотечения» даёт +53% физ.урона при +65% на всём чистом луче Силы. Поэтому ни один мой кластер в этом клине физический урон не трогает.*

**Правило Ц4.** Значение малой ноды **3–7%**, размер кластера **3–5 малых + 1 нотабл**. Это в рамках авторского «3–8%» и совпадает с грамматикой, снятой с JSON (5% сигнатурный, 3% вторичный).

### Клин СИЛА + ЛОВКОСТЬ (5 кластеров)

Тема клина: тело и скорость. Броня и уклонение вместе, пробивание, блок и подавление. Огонь и физ.урон здесь уже заняты — не трогаю (Ц3).

**S/D-1. Латная поступь**
`4 × +4% AllDefence` → нотабл `+18% AllDefence`, `+10% CriticalDamageMitigation`
Итого **+34% AllDefence** (то есть одновременно броня и уклонение).
*Обоснование:* это единственный кластер во всём дереве, который умеет масштабировать обе защиты сразу — ровно то, ради чего клин существует. По Ц1: +34% от 6 402 брони = +2 177, доля 34% — в коридоре. Прямо готовит два кейстоуна владельца из этого клина («Всё уклонение конвертируется в броню» / «Вся броня конвертируется в уклонение»): после конверсии оба процента продолжают работать на выживший параметр.

**S/D-2. Пробойник**
`3 × +4% ArmorPenetration (Flat)`, `2 × +8% Accuracy` → нотабл `+12% ArmorPenetration`, `+25% Accuracy`
Итого **+24% пробитие брони, +41% точность**.
*Обоснование:* `ArmorPenetration` на экипировке отсутствует полностью (§1.6), дерево — единственный источник. По Ц2: чистый кластер Силы «Пробитие брони» даёт +30%, здесь 24% = **80%**. Точность — ловкая половина, и она осмысленно спарена: пробить и попасть.

**S/D-3. Щит и увёртка**
`3 × +1% BlockChance (Flat)`, `2 × +4% Suppress` → нотабл `+4% BlockChance (Flat)`, `+15% BlockChance`, `+10% Suppress`
Итого **+7% шанс блока, +15% увеличение блока, +18% подавление**.
*Обоснование:* по доку владельца блок и подавление — параметры **без атрибута-источника** («живут в кластерах и на экипировке»). Клин Сила/Ловкость — их естественный дом: блок силовой, подавление ловкое. По Ц2 против чистых кластеров (Сила #4: +7% шанс/+30% увеличение; Ловкость #6: +35% подавление) — 50–100% и 51%, в коридоре с запасом вниз, потому что кластер двухпараметрический.

**S/D-4. Второе дыхание**
`3 × +5% HealthRecovery`, `2 × +4% Evade` → нотабл `+15% HealthRecovery`, `+20% Evade при здоровье ниже 30%` *(условие `Health_Below_30` уже используется в JSON — `notable_health_regen_low_life_1`)*
Итого **+30% восстановление здоровья, +8% уклонение, +20% уклонение условно**.
*Обоснование:* восстановление процентом на экипировке отсутствует; шмот даёт 327 плоско. +30% = +98, доля 30% — по Ц1 в коридоре. Условная половина повторяет фантазию чистого кластера Ловкости #8, но привязана к восстановлению, а не к чистому уклонению.

**S/D-5. Хватка исполина**
`3 × +4 AllAttribute (Flat)`, `2 × +4% Health` → нотабл `+10 AllAttribute (Flat)`, `+12% Health`, `+15% MoveSpeed`
Итого **+22 ко всем атрибутам, +20% здоровье, +15% скорость**.
*Обоснование:* прямо реализует тезис владельца «типичный билд это не луч, а луч плюс заход в клин **за базовыми статами**». Атрибутов на экипировке мало (лейт: 32–48 суммарно), +22 — это +46…+69% к атрибутному пулу, и по формуле «атрибут = 5 единиц своего параметра» это ещё и +110 здоровья, +110 уклонения, +110 маны сверху. Единственный кластер набора, который одинаково полезен любому билду — и это осознанно, клин должен приманивать.

### Клин ЛОВКОСТЬ + ИНТЕЛЛЕКТ (5 кластеров)

Тема клина: повторы, реакция, тонкая защита. Молния, кровотечение и Evade|Barrier заняты — обхожу.

**D/I-1. Многоликий удар**
`3 × +5% MulticastChance`, `2 × +5% AdditionalHitChance` → нотабл `+4% MulticastChance (Flat)`, `+18% MulticastChance`, `+4% AdditionalHitChance (Flat)`
Итого **+33% мультикаст, +4% шанс мультикаста, +10% доп.атака, +4% шанс доп.атаки**.
*Обоснование:* два «шанса повтора» из разных стоек — точный образ клина. `MulticastChance` на шмоте только плоский (+19.3% на лейте), `AdditionalHitChance` тоже (+11%). По Ц1 проценты дерева ложатся поверх и дают +33%/+10% — доля выше 100% по процентному каналу, что нормально: канала на шмоте нет. Против чистых кластеров (Интеллект в JSON: `notable_multicast_chance_1` +40%; Ловкость #9: +18% доп.атаки) — 82% и 55%, в коридоре Ц2.

**D/I-2. Барьерный рефлекс**
`3 × +6% BarrierRecovery`, `2 × +4% Evade` → нотабл `+20% BarrierRecovery`, `+12% Evade`
Итого **+38% восстановление барьера, +20% уклонение**.
*Обоснование:* **`BarrierRecovery` сейчас пуст во всех данных проекта** — ни одного ролла, ни одной ноды. Между тем это заявленный фокус Интеллекта («восстановление маны/барьера») и предмет кейстоуна владельца «45% восстановления маны применяется к восстановлению барьера». Кластер даёт этому кейстоуну что умножать. Ловкая половина — уклонение, потому что барьер и уклонение уже спарены в этом клине (`notable_evade_barrier_1`), и это продолжение той же линии, а не её дубль.

**D/I-3. Отравленный клинок**
`3 × +5% PoisonDamage`, `2 × +20 ManaOnHit (Flat)` → нотабл `+18% PoisonDamage`, `+50 ManaOnHit (Flat)`
Итого **+33% урон ядом, +90 маны за удар**.
*Обоснование:* мостит ловкий яд к интеллектовой экономике маны — отравляешь и с этого же питаешься. По Ц2 против чистого кластера Ловкости #2 (+32% увеличения + 15% мультипликатора): 33% увеличения без мультипликатора = **~78%** ценности, в коридоре. Мультипликатор намеренно не даю — он должен оставаться привилегией чистого луча и кейстоуна.

**D/I-4. Критическая формула**
`3 × +5% SpellDamage`, `2 × +5% CriticalChance` → нотабл `+3% CriticalChance (Flat)`, `+20% SpellDamage`
Итого **+35% урон способностями, +10% увеличение шанса крита, +3% шанс крита**.
*Обоснование:* `SpellDamage` **процентом на экипировке не существует** (только плоские 98/156), а крит — ловкая валюта. Кластер отвечает на вопрос «зачем ловкачу заходить к магам»: он приносит крит в способности. По Ц2 против `notable_spell_damage_1` (+40%): 35% = **88%**, чуть выше коридора — можно опустить нотабл до +18%, если владелец захочет строгости.

**D/I-5. Ускользающий разум**
`3 × +4% Suppress`, `2 × +5% Barrier` → нотабл `+10% Suppress`, `+5% SuppressChance (Flat)`, `+20% Barrier`
Итого **+22% подавление, +5% шанс подавления, +30% барьер**.
*Обоснование:* подавление снижает урон **от способности**, барьер его поглощает — две антимагические защиты в одном кластере, и обе из разных стоек. Прямо лечит дыру §3.3: барьерный пул на 38–42% тоньше броневого, а процентов барьера на шмоте нет вовсе. По Ц1: +30% от 3 989 = +1 197.

### Клин ИНТЕЛЛЕКТ + СИЛА (5 кластеров)

Тема клина: стихия в тяжёлой руке. Холод и «здоровье+барьер» заняты — обхожу.

**I/S-1. Рунная броня**
`2 × +4% Armor`, `2 × +4% Barrier` → нотабл `+18% Armor`, `+18% Barrier`
Итого **+26% броня, +26% барьер**.
*Обоснование:* два «толстых» защитных пула, которых процентами шмот не даёт вовсе. Отличается от `notable_health_barrier_1` (там здоровье, не броня). По Ц1: +26% от 6 402 = +1 665 брони и +26% от 3 989 = +1 037 барьера; доля 26% — нижняя граница коридора, намеренно, потому что кластер бьёт по двум пулам сразу.

**I/S-2. Стихийный молот**
`3 × +4% AllElementalDamage`, `2 × +5% PhysicalDamage` → нотабл `+15% AllElementalDamage`, `+15% PhysicalDamage`
Итого **+27% весь элементальный урон, +25% физический урон**.
*Обоснование:* единственный кластер, дающий `AllElementalDamage` — агрегат реализован (`AggregateParameters.cs:22`), но в данных не встречается ни разу. Прямая подводка к кейстоуну владельца из этого же клина «Весь элементальный урон увеличен на 35%. Атаки не наносят физический урон»: кластер даёт выбор — взять кейстоун и потерять физическую половину, или не брать и жить гибридом. Ц3 соблюдён: +25% физ.урона против +65% на чистом луче Силы, и в этом клине других источников физ.урона нет.

**I/S-3. Тигель**
`3 × +5% HealingEfficiency`, `2 × +6% BarrierRecovery` → нотабл `+15% HealingEfficiency`, `+20% BarrierRecovery`
Итого **+30% эффективность лечения, +32% восстановление барьера**.
*Обоснование:* силовые восстановления встречаются с интеллектовым барьером. `HealingEfficiency` на экипировке отсутствует; `BarrierRecovery` пуст везде. Второй из двух кластеров набора, наполняющих `BarrierRecovery` — сознательно, у параметра сейчас ноль носителей, и одного кластера на всё дерево ему мало.

**I/S-4. Незыблемость**
`3 × +5% DamageTakenReductionFromAbility`, `2 × +4% CriticalDamageMitigation (Flat)` → нотабл `+15% DamageTakenReductionFromAbility`, `+8% CriticalDamageMitigation`
Итого **+30% снижение урона от способностей, +16% смягчение крит.урона**.
*Обоснование:* `DamageTakenReductionFromAbility` в данных встречается один раз и не на дереве; чистый луч Силы закрывает только `...FromAttack` (`notable_reduce_damage_taken_from_attack_1`). Клин с Интеллектом — правильное место для защиты именно от способностей. `CriticalDamageMitigation` уже стоит в клине Сила/Ловкость, но здесь он вторичная половина, а не тема, — пересечение считаю допустимым; если владелец против, заменяется на `DamageTakenReductionFromEffect`.

**I/S-5. Ритм битвы**
`3 × +3% CooldownResetChance`, `2 × +4% Health` → нотабл `+8% CooldownResetChance`, `+15% Health`
Итого **+17% шанс сброса перезарядки, +23% здоровье**.
*Обоснование:* `CooldownResetChance` реализован и в дереве не используется. Это интеллектовая «частота способностей», оплаченная силовым здоровьем — тематически рядом с авторским кластером «Эффективность бафов» в этом же клине, но не дублирует его. Значения намеренно скромные: сброс перезарядки — множитель на весь темп боя, ему опасно давать много.

Стоимость: 15 кластеров × 4–6 нод = **68–86 нод**. Это больше одного бюджета (65) — и должно быть: клинья заполняются на выбор, не берутся целиком.

**Побочный эффект набора:** восемь из пятнадцати кластеров бьют по параметрам, у которых сейчас **ноль** носителей в данных или ноль процентного канала на экипировке — `AllDefence`, `AllElementalDamage`, `BarrierRecovery` (дважды), `CooldownResetChance`, `DamageTakenReductionFromAbility`, `ArmorPenetration`, `SpellDamage`%. Это не совпадение: инвентаризация §1.6 показала, где у системы дыры, и клинья — естественное место их закрыть.
