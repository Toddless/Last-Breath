# Dual-grid тайлсет: суть техники и план реализации

Источник: «Draw fewer tiles — by using a Dual-Grid system!» (jess::codes, техника Оскара Столберга) + её референс-реализация для Godot. План адаптирован под наш стек: Godot 4.7, `TileMapLayer`, стиль C, базовый грунт `SharedData/Assets/Tiles/Forest_Ground_Base.png`.

## 1. Суть техники

**Проблема классического автотайлинга.** Стандартный блоб-автотайл рисует границы террейна ПО ЦЕНТРУ клетки и требует 47 тайлов (полный набор соседств из 256 конфигураций после дедупа); 15-тайловый упрощённый набор даёт кривые стыки, а одинаково скруглить внутренние и внешние углы почти невозможно. Каждый новый террейн или анимация умножает объём арта (пример из видео: 11-кадровая анимация воды — 507 тайлов классикой против 155 на dual-grid).

**Решение.** Две сетки:
- **Мировая (данные)** — невидимая; каждая клетка хранит только «какой террейн» (для пары террейнов — бит).
- **Дисплейная (визуал)** — сдвинута на **полклетки** по X и Y; каждый её тайл накрывает **углы четырёх** мировых клеток.

Дисплейный тайл выбирается по состоянию своих четырёх углов: 2⁴ = **16 конфигураций → 16 тайлов** на пару террейнов (при симметричном арте — до 6). Границы при этом проходят между мировыми клетками — стыки бесшовные, углы скруглены одинаково, геймплейная сетка (проходимость, клики) остаётся честной мировой и не знает о визуале.

**Цена.** Набор тайлов — на ПАРУ террейнов (трава↔грязь, трава↔вода...): N взаимно граничащих террейнов = попарные наборы или слоёная композиция «каждый террейн поверх базы». Для нашего мира со слоями-подложками это штатный путь: базовый грунт всегда снизу, каждый следующий террейн — свой dual-grid-слой с прозрачностью.

## 2. Архитектура у нас (Godot 4.7)

Компонент `DualGridTerrainLayer` (Node2D, C#), инкапсулирует пару слоёв:

- `_world : TileMapLayer` — данные, невидимый (или вообще словарь `Vector2I → bool`, если мировая сетка уже есть у другого владельца); клетка = «террейн присутствует».
- `_display : TileMapLayer` — визуал, `Position = tileSize / 2` (сдвиг на полклетки); заполняется только кодом.
- **Таблица 16 правил**: битовая маска четырёх углов (TL, TR, BL, BR — мировые клетки, которые накрывает дисплейный тайл) → атлас-координата в тайлсете. Единственная точка правды, константный словарь.
- `SetCell(coords, present)` / `FillRect` / `Clear`: правка мировой клетки инвалидирует ровно **четыре** дисплейных тайла, которые её накрывают, — точечный пересчёт, без полного скана.
- Загрузка карты: один проход по мировым данным → массовое заполнение дисплея.

Интеграция: MainWorld держит базовый грунт обычным `TileMapLayer` с `Forest_Ground_Base` (фон, без автотайлинга — он бесшовный сам по себе), а каждый «накладной» террейн — своим `DualGridTerrainLayer`. Шейдер/шум поверх базы живёт на слое базы и dual-grid не трогает.

Редактирование уровня: на первом этапе — правка мировых данных кодом/инспектором; полноценная кисть в редакторе Godot (TileMap-плагин) — отдельный этап, если понадобится (мировой слой можно рисовать штатной кистью Godot по невидимому TileMapLayer — компонент подхватит его содержимое на `_Ready` и на сигнале изменений).

## 3. Арт-конвейер 16-тайлового листа (nano banana)

Тайл границы = переход «террейн A ↦ террейн B» в одном из 16 угловых сочетаний. План генерации:

1. Базовые текстуры обоих террейнов уже бесшовные (конвейер тайлов: жёсткая бесшовность в промпте + контроль замосткой 2×2).
2. Генерируем **один лист переходов**: якорь — обе базовые текстуры, промпт — «4×4 атлас переходов травы в грязь, границы через середины тайлов, рваная органическая кромка в стиле штриховки»; при нестабильности — генерируем 3–4 ключевых тайла (прямая кромка, внешний угол, внутренний угол, диагональ) и добираем остальные поворотами/отражениями в ImageMagick (симметричный набор ≈ 6 уникальных).
3. Контроль: собрать тестовую карту-шахматку скриптом и посмотреть глазами все 16 стыков.
4. Раскладка атласа — фиксированная (4×4, порядок масок 0b0000…0b1111), чтобы таблица правил в коде не зависела от конкретной пары террейнов: новый переход = новый PNG с той же раскладкой.

## 4. Этапы реализации

| # | Этап | Скоуп |
|---|---|---|
| 1 | Ядро | `DualGridTerrainLayer` (Core-логика таблицы масок — чистый C#, тестируемо; Godot-обвязка тонкая), тестовая сцена-песочница, набор-заглушка 16 тайлов (контрастные цвета) для проверки правил |
| 2 | Арт | Лист переходов «лесной грунт ↦ тропа/грязь» конвейером §3, замена заглушки |
| 3 | Мир | Слой в MainWorld поверх базового грунта; правка данных — кистью по невидимому мировому слою |
| 4 | Позже | Второй террейн (вода?), анимированные переходы (16 кадровых наборов), кисть-плагин если штатной не хватит |

Пины этапа 1 (Godot-free): таблица 16 масок тотальна и уникальна; правка клетки инвалидирует ровно 4 дисплейных адреса; преобразование координат мир↔дисплей обратимо, включая отрицательные координаты (известная ловушка реализации из видео).

## 5. Открытые вопросы владельцу

1. Первая пара террейнов: лесной грунт ↦ что? (тропа/грязь — самый ходовой кандидат для демо).
2. Размер клетки мировой сетки для террейна (текущая мировая сетка/масштаб спрайтов — от этого размер тайла атласа).
3. Кто владелец мировых данных террейна: отдельный невидимый TileMapLayer на сцене (рисуется штатной кистью) или данные в json/сейве.
