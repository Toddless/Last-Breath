# Аугменты, сокеты и орнаменты

Статус: описание существующей реализации. Основа и границы статической сверки — [в отчёте](../Guidelines/SystemDocumentationAudit.md).

## Устройство и поведение

- **Аугмент — предмет.** `AbilityAugmentData` задаёт запись каталога и шкалу значений по редкости. `AugmentMinter` выбирает редкость в диапазоне записи; числа экземпляра определяются ступенью `AugmentValueLadder`, а не независимым разбросом ±25%. При наличии `EffectPool` дополнительно выбирается эффект. `AugmentInstance` хранит ID записи, значения, редкость и выбранный `EffectId`; `AugmentItem` занимает отдельный слот сумки. `Applied(record)` подставляет сохранённые числа и выбранный эффект при создании носимого улучшения.
- **Конверсия 3→1**: `ConvertAugmentsRequestHandler` проверяет три разных экземпляра, наличие записей каталога и совпадение `Tier` и `Rarity` именно у записей. Выбирает альтернативную запись того же класса, не входящую в предложенные, создаёт новый предмет, сначала добавляет его в сумку и только затем удаляет исходные три. При отсутствии места операция отклоняется. Это описание текущего кода: сравнение редкости записей нельзя подменять утверждением о сравнении редкости экземпляров.
- **Подгонка — ОДНО МЕСТО**, `AugmentFit.Check`: непротиворечивость записи → тир (сокет тира N берёт запись тира ≤ N) → привязка (`abilityId` решает один, иначе пересечение собственных или выданных установленными аугментами тегов `SharesAny`, `OrdinalIgnoreCase`; `fitsAnyAbility` — универсальный) → группа исключения. Интерфейс НЕ ИМЕЕТ ПРАВА мерить тиры и теги сам: два прочтения одного правила — два ответа. Тег обещает подгонку, а не работу (аугмент может подойти и ничего не делать).
- **Доска сокетов** `IAbilitySocketBoard` — слот адресуется строкой `socketId|abilityId|tier`, а не id узла. Набор слотов даёт аллокация дерева (`Sync`), содержимое — её собственность (сейвится). **Слот с аугментом переживает потерю своего узла**: закрывается и пускает только наружу («только вынуть»), пустой исчезает. Респек не уничтожает имущество игрока.
- **Ворота — хендлеры, интерфейс зеркалит**: `InstallAugmentRequest`/`ExtractAugmentRequest` через шину, `IAugmentInstallGate` — единственная точка посадки (сумка → есть ли слот → закрыт → занят → правило). Извлечение кладёт в сумку ДО того, как слот отпустит копию: числа роллятся один раз и восстановлению не подлежат.
- **Способность носит ровно то, что стоит в её сокетах** — `IAbilityAugmentBinder.Bind()`, тотальная пересборка (снос и сборка целиком), не инкрементальная. Зовут её ПЯТЬ дорог: посадка, извлечение, `Reconcile` (Sync/аллокация/смена игрока), загрузка сейва, сессионный сброс. Числа берутся у КОПИИ (`AbilityProvider.CreateUpgrade(AugmentInstance)` → `instance.Applied(record)`), не у записи.
- **Соперничество (2026-08-07)**: два аугмента с ОДНИМ ЭФФЕКТОМ не складываются — работает сильнейший, проигравший остаётся в слоте спящим и оживает при извлечении победителя. Идентичность эффекта — `AbilityEffectIdentity` (параметр + направление, НИКОГДА величина; родня `LineIdentity` из крафта). Сравнение настоящее: оба применяются к недекорированной базе, дальше от базы = сильнее. Решается НА ЧТЕНИИ (`AbilityParameterSet.GetValue`), поэтому от порядка посадки не зависит. **Цена — исключение**: у ухудшающих движений (`AbilityParameter.CastPrices` = Cooldown, CostValue) в идентичность входит id записи, иначе игрок получал бы скидку за то, что надел больше платных аугментов. **Пол перезарядки**: долевые срезы кулдауна не опускают его ниже 1 (`AbilityParameter.MinimumCooldown`) — аугмент продаёт короткую перезарядку, а не её отсутствие; нулевой базы пол не касается (мгновенный каст остаётся мгновенным), плоские срезы авторских апгрейдов проходят мимо пола осознанно.
- **Орнаменты — четвёртый сокет (2026-08-17)**: предмет (`OrnamentItem`, каталог `SharedData/Ornaments`, по одному на тир, источник — только квесты линейки испытаний), надетый на способность, даёт ей **+1 сокет своего тира**; **один орнамент на способность** → максимум 4 аугмента (2 одного тира + по 1 остальных). Владелец состояния — доска (`AbilityOrnament` = ornamentId|abilityId|tier; socketId сокета = id орнамента, адрес обычный): `Sync` объединяет сокеты аллокации с орнаментными, поэтому **респек орнамент не трогает**, а инвариант «один на способность» стоит на доске и обязателен для всех дорог, включая загрузку. Снятие — **только при пустом сокете** (`remove-only`, как у слота без узла: иначе аугмент переехал бы на способность с другими тегами); отсюда следствие — посадка/снятие орнамента НЕ меняет носимое, и `Bind()` на этих дорогах не зовётся. Ворота — `IOrnamentAttachGate` + `AttachOrnamentRequest`/`DetachOrnamentRequest`; единственный гейт по дизайну — способность открыта (открытый сокет того же тира НЕ требуется). Числа орнамент не роллит, поэтому сумочная копия при снятии **чеканится заново**.
- Сейв: секция `abilityBook` **v9**, `sockets` — список записей с адресом, роллёнными числами и подписью слота; `ornaments` — пары «орнамент↔способность» (тир НЕ пишется, берётся из каталога), едут ОДНИМ вызовом `Restore` вместе с посадками (половина восстановленной раскладки = потерянный четвёртый сокет; сам порядок внутри вызова не несущий — закрытый слот, поднятый записью, переоткрывается посадкой орнамента). **Отвергнутая запись НЕ теряется** (надетый орнамент не лежит в сумке, а выдаётся одним неповторяемым квестом ⇒ потеря перманентна): доска ВОЗВРАЩАЕТ вытесненные орнаменты вызывающему, участник чеканит их в сумку; если чеканить нечем (запись id пропала) или в сумке нет места — запись переносится в СЛЕДУЮЩИЙ сейв как есть (`_unplaceable`, чистится каждым ресторе и `RestoreWithoutSection`, чтобы не течь в новую игру). Исключение — файл, назвавший ОДИН орнамент дважды: он уже на способности, возврат сделал бы второй экземпляр уникума ⇒ дубль громко отбрасывается. **секции `upgrades` больше нет** (описывала бесплатный выбор). Старые версии читаются от 4-й (файл до 7-й = орнаментов нет), отброшенные выборы называются в Tracker.

## Уточнения текущей реализации

- Запись с одновременно заданными `fitsAnyAbility` и `abilityId` отклоняется как противоречивая. Извлечение донора тегов не запускает повторную проверку подгонки уже установленных аугментов.
- `AbilityAugmentBinder` читает `WorkingAugment`: содержимое закрытого сокета сохраняется как имущество, но не усиливает способность.
- В `abilityBook` v8 редкость аугмента записывается именем, v9 добавляет оставшиеся перезарядки способностей. Старые файлы без этого поля означают отсутствие оставшейся перезарядки. Минимальная читаемая версия — 4.
