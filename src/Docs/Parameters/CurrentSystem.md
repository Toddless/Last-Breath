# Параметры сущностей и модификаторы

Статус: описание существующей реализации. Основа и границы статической сверки — [в отчёте](../Guidelines/SystemDocumentationAudit.md).

## Устройство и поведение

- ParameterModifiersComponent содержит список модификаторов сущности. В большинстве случаев сущность получает модификаторы от экипировки (больше всего относится к Игроку), атрибутов (Dex, Int, Str), пассивок, реже от эффектов.
Задача данного компонента: Хранение списка модификаторов цели и уведомление об изменениях списка модификаторов для параметра.
Для нпс имеется дополнительный источник модификаторов: INpcModifier.
- EntityParametersComponent содержит значения параметров сущности. Работает в связке c ParameterModifiersComponent (неявно посредством подписки на EventHandler<IModifiersChangedEventArgs>? ModifiersChanged). При получении уведомления об изменении модификаторов параметра пересчитывает значение и сохраняет в Current. Все значения рассчитываются по схожей формуле: (base + сумма flat) × (1 + сумма increased) × (1 + сумма multiplicative). Параметры сущности затем могут быть изменены посредством декораторов.
Задача компонента: Хранение, расчет и уведомление об изменении значения параметра.
- NpcModifier хранит список модификаторов наложенных на нпс. Один из источников модификаторов значений параметров для нпс.

## Контекстные модификаторы

- ModifierHandlerComponent хранит пайплайны обработки контекстов. IContextModifier<T> используется для модификации цифровых значений атаки, лечения, урона и активации способностей. Порядок применения — семантическая шкала `ContextModifierPriority` (Early −100 / Innate −50 / Normal 0 / Late 100 / Absolute 1000 / Remainder 1500 / Denial 2000). Absolute — конверсии, берущие ДОЛЮ компоненты (мифик «40% физа в огонь»); Remainder — правила, забирающие ОСТАТОК компоненты (Триединство троит весь оставшийся физ) — отдельный слот, потому что сортировка списка нестабильна и ничьи на одном приоритете не упорядочены; Denial — правило, ЗАКАНЧИВАЮЩЕЕ компоненту («атаки не наносят физический урон»): всё, у кого есть право на часть компоненты, берёт её на Remainder или раньше, поэтому конвертированное переживает отказ, а гасится только неконвертированный остаток.
- **Ручки мифических клейм (2026-07-20)**: 17 новых членов `ContextParameter` с биндингами — конверсия физического в стихию (`PhysicalToFire/Cold/Lightning`, по элементу на запись), `AttacksIgnoreResistances` (flag), добавленный стихийный от атак (`AddedFire/Cold/LightningDamage`), `AttackSacredConversion`, `CooldownResetChance`/`FreeCastChance` (роллят на `IAbilityActivationContext.Rnd`), `DotDamageBonus` (маска Bleed|Poison|Burning — «удвоение урона эффектов» и «Яд/Кровь/Горение +X%» это ОДНА ручка, две записи пула), `EffectDurationScale` (умножение длительности всех эффектов), четыре `DamageTakenReductionFrom*` по `DamageCause` и `DotDamageTakenReduction` (по компонентам урона). Урон-мутаторы гейтятся по владельцу, поэтому строятся в `Attach` (`DamageBinding`). Инвариант «у каждого члена есть биндинг» держит `ContextModifierBindingTests`.

Параметры пересчитываются через `Calculations.CalculateFloatValue`. После декораторов `EntityParametersComponent` применяет ограничения параметра; для полностью конвертированного пула возвращает ноль. Максимумы сопротивлений — отдельные параметры: сопротивление сверх максимума сохраняется как запас против снижения сопротивления, но при митигации используется ограниченное значение.
