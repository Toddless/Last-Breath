# Общее взаимодействие, сундуки и NPC

Статус: описание существующей реализации (после доработки #265 и #680, 2026-09-28). Контракт и проект — в [архитектуре взаимодействия](InteractionArchitecture.md); основа и границы сверки — [в отчёте](../Guidelines/SystemDocumentationAudit.md).

## Выбор цели

- У игрока один `PlayerInteractionController` — Area2D-датчик на слое обнаружения 16 (`InteractionTarget.DetectionLayer`). Его позиция — точка взаимодействия игрока (`InteractionOrigin`), от неё меряются дистанция и луч.
- Кандидаты — цели, в круг обнаружения которых вошёл датчик (`AreaEntered`/`AreaExited`). Полного обхода локации нет.
- Дистанция и препятствия пересчитываются только для кандидатов, раз в `RefreshSeconds` (0,1 с) в физическом цикле. Препятствия — слои `ObstacleMask` цели; собственные тела цели (`OwnBodies`) и игрока луч не закрывают. Запрос луча переиспользуется, без выделений на каждый луч.
- Выбирается ближайший кандидат с доступным действием; если доступных нет — ближайший досягаемый с видимыми недоступными действиями, и подсказка показывает причину.

## Цель и её настройка

- `InteractionTarget` (Area2D) — идентичность, точки, якорь подсказки и круг обнаружения. Идентичность и доступность даёт владелец (`IInteractionOwner`: ближайший предок-владелец); ID собирается `InteractionIds` с префиксом вида: `chest/`, `endpoint/`, `npc/`.
- В сцене задаются: `InteractionPoints` (Marker2D; без них — позиция цели), `HintAnchor`, `OwnBodies`, `Reach` (по умолчанию 150) и `DiscoveryShape` — прямой ребёнок с кругом по центру цели, покрывающим все точки плюс `Reach`. Любая другая настройка круга отключает цель с одним отчётом в Tracker.
- Узел-владелец проверяет свою цель через `InteractionTargetSetup.FindProblem`: цели нет, она чужая или не прямой ребёнок — объект отключается с отчётом.
- Действия цели кэшируются (`CachedOffer`). Кэш сбрасывается, когда цель становится кандидатом, после каждой команды, при возобновлении обнаружения и когда владелец сообщает о смене предложения (`InvalidateOffer`). Перед выполнением действия читаются заново (`ReadActions`).

## Ввод, подсказка и меню

- E (`Settings.Interact`) принимает только контроллер, один раз; фокус текстового поля глушит мировые действия. Команда ставится на ближайший физический тик, показанная цель проверяется заново, затем действие выполняется.
- Одно доступное действие выполняется сразу; несколько открывают `InteractionMenuWindow`. Действие с `ExplicitChoice` (атака и другие опасные) всегда требует выбора в меню, даже оставшись единственным.
- Подсказка выбирает текст по числу доступных действий: ни одного — причина первого действия (иначе Unavailable); одно — клавиша и его глагол; несколько — клавиша и «Взаимодействовать». Текст пересобирается только при смене выбора или его списка действий; положение следует за целью каждый кадр.
- Меню строится из сцен `InteractionActionRow` (причина недоступности, опасный стиль) по предложению на момент открытия и перестраивается, когда у цели появился новый список. Начальный фокус — первое доступное действие без явного выбора; при перестройке фокус остаётся на том же действии.

## Сессия и результат

- `InteractionService` держит одну сессию, привязанную к цели (`IInteractionSession`: цель, окно, `IsOpen`, `End(cause)`). Меню и окно сундука — сессии через базу `InteractionWindow`. Окно сессии блокирует ходьбу игрока, мир продолжает жить.
- Новая сессия заменяет прежнюю (`Replaced`) и сбрасывает ожидающую команду. Проверка сессии выводит причину в порядке актёр → жизненный цикл цели → досягаемость: `ActorUnavailable`, `TargetLost`, `OutOfReach`; явная отмена — `Cancelled`.
- Результат команды — `InteractionResult(Outcome, ReasonKey)`: `Completed` (эффект готов к ответу), `Started` (передано сессии или процессу: меню, окно, диалог, бой), `Refused`. `InteractionResult.Dropped` — команда, которая не выполнялась (без причины).

## Отказ и обратная связь

- Обратная связь в одном месте — `InteractionService`: результат с причиной даёт звук отказа (`PlayerInteractionController.RefusalSound`) и одно оповещение `SendNotificationMessageMessage` в системной ленте. Источники только возвращают ключ причины.
- Команда, которая не выполнялась (сброшенная сменой сессии, отказ «занято», контроллер вне дерева), и любое завершение сессии молчат.

## Сундук

- Каталог `ChestCatalog` читает `SharedData/Chests`: `id`, `nameKey`, `capacity`, `emptyRemovalDelayMinutes`, `access` (`Unlocked`), `contents` (`Authored`, позиции `slotId`/`itemId`/`amount`/`rarity`). Разбор строгий: битая запись — отчёт в Tracker и пропуск только её. Вместимость — положительное число, вмещающее авторские позиции. Описатель для редактора данных — `ChestsCatalogDescriptor`.
- `ChestComponent` — корень `Chest.tscn` и владелец цели сундука (`InteractionIds.Chest(ObjectId)`); ссылка `Target` в сцене обязана вести на прямого ребёнка. Содержимое создаётся при первом открытии (`AuthoredChestMinter`: авторская редкость, без бонус-эффектов); подсказка содержимое не создаёт.
- `ChestContents` владеет слотами и абсолютным сроком удаления. Состояние сохраняется через `ILocationStateParticipant`: конкретные предметы, остатки слотов, срок. Нечитаемое сохранённое состояние удерживается для следующего сохранения, а не теряется.
- Облик: закрытый, открытый и пустой (текстуры в сцене).
- Окно `ChestContentsWindow` — сетка ячеек в облике слота сумки (`InventorySlot.tscn`): ячеек `max(вместимость, число слотов)`, слот i — в ячейке i, опустевший слот оставляет пустую ячейку на месте. Наведение показывает общий тултип предмета (`ItemTooltipPopup`); кнопки действий тултипа есть только у предметов сумки. Ячейки сундука не участвуют в перетаскивании.
- ПКМ по ячейке (с любым модификатором) переносит её слот; R или «Забрать всё» перебирают все слоты. Переносится то, что помещается, включая часть стака; отказ в одном слоте не мешает следующим. Остатки источника фиксируются до уведомлений инвентаря (`IInventoryTransfer.ReceiveUpTo`). Переполнение сумки — причина `UI_Container_Full`, одно оповещение на команду.
- Пустой сундук исчезает через `emptyRemovalDelayMinutes` игровых минут: сохраняется абсолютный срок, сундук слушает `IWorldClock.MinutePassed` только пока срок назначен; удаление — tombstone локации.
- Первый сундук — `StarterChest` в SourceOfPowerNearVillage: `DefinitionId` Chest_Starter, `ObjectId` starter_chest, вместимость 20, пять Uncommon-предметов (кинжал, шлем, перчатки, сапоги `Boots_Stone_Tread`, доспех).

## Выходы

- Цели выходов лежат в сценах локаций у своих `LocationEndpoint` (владелец — endpoint, ID `endpoint/<EndpointId>`), `Reach` 180. E у выхода выполняет переход.

## NPC

- TestNpc содержит NpcInteractionTarget с DialogueActor и NpcAttackActionSource. Разговор запускается через E/меню; старой кликовой области нет. Атака всегда требует явного выбора, включая случай единственного действия.
- IDialogueService.CanStart и Start разрешают вход одним способом. INarrativeCondition.IsPreviewSafe — явное разрешение предварительной проверки; по умолчанию false, составные условия требуют безопасности каждого ребёнка. QuestOfferRoll и косвенный CanAcceptQuest запрещены во входах, но сохраняют работу в репликах.
- BaseNpc.TryStartBattleWith объединяет контакт и явную атаку. BattleContext помечает только принятых участников; нельзя использовать уведомление Attacked всей группе для установки IsFighting. Позиция/пространство шума фиксируются до переноса в арену.
- InteractionTarget регистрируется при каждом входе в дерево локации и получает новую привязку; NPC использует InstanceId. Смерть/бой/преграда закрывают меню, уход или удаление собеседника завершают принадлежащий ему диалог. Статические собеседники используют обычную цель и авторские параметры DialogueActor.
