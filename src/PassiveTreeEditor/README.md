# Passive Tree Editor

Отдельный инструмент для проектирования и балансировки дерева боевых искусств. Живёт своим
Godot-проектом рядом с игрой, ссылается только на `Core` и **ничего не меняет за пределами
собственной папки**. В игру не интегрирован — это отдельный шаг.

Главный артефакт инструмента — не редактор, а **JSON-файл дерева**. Редактор существует, чтобы его
удобно писать.

---

## Запуск

1. Открыть Godot 4.7 mono → **Import** → выбрать `src/PassiveTreeEditor/project.godot`.
   Первый импорт долгий: через симлинк `Data/Shared` в проект попадает весь `SharedData`.
2. Godot предложит собрать C#-решение (`Build`). Собирается `PassiveTreeEditor.csproj`
   с `ProjectReference` на `..\Core\Core.csproj`.
3. **F5** (главная сцена — `main.tscn`).

Проект не добавлен в `src/Main/LastBreath.sln` — это файл вне папки инструмента, трогать его
запрещено условиями задачи. Чтобы видеть проект в IDE, добавьте его в решение вручную.

Данные читаются через симлинк `Data/Shared → ../../SharedData` — ровно так же, как в остальных
четырёх проектах.

## Формат данных

### Где лежит

`SharedData/PassiveTree/PassiveTree.json` — новый каталог данных рядом с `Abilities`,
`CombatRules` и прочими. Путь настраивается в шапке окна; при первом сохранении каталог создаётся.

Один файл = одно дерево. Если в каталоге окажется несколько json, победит последний прочитанный.

### Схема

```json
{
    "version": 1,
    "budget": 62,
    "nodes": [
        {
            "id": "str_armor_1",
            "kind": "Small",
            "stance": "Strength",
            "x": 240.0,
            "y": -120.0,
            "title": "",
            "description": "",
            "abilityId": "",
            "modifiers": [
                {
                    "parameter": "Armor",
                    "valueType": "Increase",
                    "value": 0.06,
                    "condition": ""
                }
            ]
        }
    ],
    "edges": [
        { "from": "str_armor_1", "to": "start_str" }
    ]
}
```

#### Корень

| Ключ | Тип | Смысл |
|---|---|---|
| `version` | int | Версия формата. Растёт только когда старые файлы перестают читаться корректно. |
| `budget` | int | Очков у игрока к капу мастерства. По умолчанию 62 (дизайн-диапазон 60–65). |
| `nodes` | array | Узлы, **отсортированы по `id`** (ordinal). |
| `edges` | array | Рёбра, ненаправленные. |

#### Узел

| Ключ | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | string | да | Идентичность узла. По нему адресуются рёбра и распределение. |
| `kind` | string | да | Класс узла (см. ниже). |
| `stance` | string | нет | `Dexterity` / `Strength` / `Intelligence`. Отсутствует — нейтральное ядро. |
| `hybridStance` | string | нет | Вторая стойка узла-перехода на клине. Есть только у гибридов; без `stance` игнорируется. |
| `x`, `y` | float | да | Координаты. Холст не ограничен, начало координат — центр колеса. |
| `title` | string | нет | Отображаемое имя (в игре станет ключом локализации). |
| `description` | string | нет | Текст правила кейстоуна; у прочих — заметка автора. |
| `abilityId` | string | нет | Id способности из `SharedData/Abilities/BaseAbilityData.json`. |
| `modifiers` | array | нет | Строки модификаторов. |

#### Строка модификатора

| Ключ | Тип | Смысл |
|---|---|---|
| `parameter` | string | Член `Core.Enums.EntityParameter`. |
| `valueType` | string | `Flat` / `Increase` / `Multiplicative`. |
| `value` | float | Доля, как везде в игровых данных: `0.06` = +6%. Для `Flat` — сырая величина. |
| `condition` | string | Свободный текст условия; пусто = безусловная. |

`Flag` в `valueType` не допускается: он легален только на `ContextParameter`, а строка дерева
всегда целится в `EntityParameter`.

Агрегаты (`AllAttribute`, `AllResistance`, `AllDefence`, `AllResistancePenetration`) разрешены —
сумматор разворачивает их по членам семьи ровно так, как это делает игра.

#### Ребро

`{ "from": ..., "to": ... }`. Ребро ненаправленное; концы нормализованы (`from` < `to` ordinal),
поэтому зеркальных дублей в файле не бывает.

#### Классы узлов

| `kind` | Строк модификатора | Ссылка на способность | Стоит очко |
|---|---|---|---|
| `Small` | ровно 1; гибрид — до 2 | — | да |
| `Notable` | 1–3 | — | да |
| `Keystone` | 0–3 + текст правила | — | да |
| `AbilityUnlock` | 0 | обязательна | да |
| `SocketTier2` | 0 | обязательна | да |
| `SocketTier3` | 0 | обязательна | да |
| `Start` | 0 | обязательна | **нет** |

Сокет Т1 отдельным узлом не является — он приходит вместе с `AbilityUnlock`.

### Гарантии записи

* **Детерминированность.** Узлы сортируются по `id`, рёбра нормализуются и сортируются, позиции
  округляются до 2 знаков, значения — до 4. Одно и то же дерево всегда даёт одни и те же байты.
* **Круговой цикл без потерь.** `загрузил → сохранил` не меняет файл: округление идемпотентно,
  пустые поля опускаются на записи и восстанавливаются в пустую строку на чтении.
* **Git-дружелюбие.** Отступ 4 пробела, перевод строки `\n` (репозиторий нормализован на LF через
  `.gitattributes`), UTF-8 без BOM, финальный перевод строки. Перетаскивание узла даёт diff в две
  строки, а не перетасовку файла.
* **Строгий разбор enum'ов.** Через `Core.Data.EnumParser` — та же политика, что у остальных
  игровых данных: опечатка роняет запись с сообщением, а не молча даёт первый член enum'а.
  Битая запись пропускается, остальной файл грузится (зеркало политики `GameDataService`).

### Как это прочитает игра

Формат не требует конвертации. `Source/Io/PassiveTreeProvider.cs` — готовый
`IGameDataParticipant`, инструмент сам грузит дерево через него. Чтобы подключить к игре:

1. Добавить `public const string PassiveTree = "PassiveTree";` в `Core.Data.GameData.DataCatalog`.
2. Перенести `PassiveTreeProvider`, `PassiveTreeSerializer`, DTO и модель в `Core`.
3. Зарегистрировать: `services.AddGameDataParticipant<IPassiveTreeProvider, PassiveTreeProvider>();`

Дальше по техбазе (`Боевые искусства — техническая база.md`) дерево реализует
`Core.Entity.Components.IParameterModifierSource`, а снятие узла — `RemoveModifierBySource(nodeId)`.

## Выбор способа отрисовки

Взят **кастомный `Control` с ручной отрисовкой в `_Draw`** и собственной матрицей мира,
без `GraphEdit`/`GraphNode` и без `Camera2D`.

**Почему не `GraphEdit`.** Он заточен под порты и слоты: соединение живёт между конкретными
слотами конкретных `GraphNode`, а у дерева пассивок ребро — это просто пара id. Каждый узел там
обязан быть отдельным `Control`-ом со своим стилем; на 500 узлах это 500 нод в дереве сцены с
неуправляемым хит-тестом и без возможности вмешаться в culling. Внешний вид (шестиугольник
кейстоуна, ромб сокета Т3, свечение ядра) через тему `GraphNode` не выражается.

**Почему не `Camera2D`.** Камера двигает весь вьюпорт, а панели редактора — `Control`-ы в том же
дереве. Пришлось бы разводить их по `CanvasLayer` и держать две системы координат. При ручной
матрице холст остаётся обычным `Control`-ом внутри `HBoxContainer` и не мешает разметке.

**Что это даёт.** Мир→экран считается вручную (`ToScreen`/`ToWorld`), поэтому явно управляемо, что
масштабируется, а что нет: радиусы узлов и толщина рёбер — да, подписи гаснут ниже порога зума
(`LabelZoomThreshold`), а не превращаются в кашу.

**Виртуализация — сразу, а не потом.** `NodeSpatialIndex` — равномерная сетка (ячейка 160 мировых
единиц), она же обслуживает и отрисовку, и попадание курсора:

* отрисовка узлов — запрос по видимому прямоугольнику, стоимость ∝ видимому, а не размеру дерева;
* попадание — запрос по маленькой рамке вокруг курсора, O(1) вместо перебора;
* рёбра отсекаются по AABB отрезка (на ~700 рёбер отдельный индекс не окупается);
* индекс перестраивается **лениво**, по флагу: загрузка добавляет узлы по одному, и перестройка
  на каждую вставку сделала бы загрузку квадратичной.

Дополнительно: минимальный радиус попадания в экранных пикселях, чтобы мелкий узел оставался
кликабельным на общем плане.

## Визуальный язык

Портирован из макета «Umbral — Passive Tree / Wheel»: палитра, формы, размеры и состояния взяты
из него один в один, поэтому дерево, разложенное по кольцам макета, выглядит как макет.

**Форма = класс узла** (радиусы — в мировых единицах, как в макете):

| Класс | Форма | Размер |
|---|---|---|
| `Small` | круг | 5.6 |
| `Notable` | шестиугольник | 12 |
| `Keystone` | шестиугольник, повёрнут на 22.5° | 17 |
| `AbilityUnlock` | круг | 11 |
| `SocketTier2` | квадрат | 6 (полуразмер) |
| `SocketTier3` | ромб | 7.5 (полуразмер) |
| `Start` | круг | 14 |

**Цвет = зона**: лучи — Сила `#c65340`, Ловкость `#6f9e55`, Интеллект `#4d84bd`. Гибрид (заполнены
и `stance`, и `hybridStance`) красится цветом своего клина: Сила+Ловкость `#b08432`,
Ловкость+Интеллект `#2f8f8a`, Интеллект+Сила `#8a63ad` — узел перехода не читается ни как один из
двух лучей, ни как соседний клин. Узлы вообще без стойки (ядро) — золото `#d8b45e`.

**Гибридный малый узел** может нести две строки вместо одной: черновик допускает обе записи
перехода — одну агрегатную (`AllAttribute`) или по строке на стойку («+2 Силы и +2 Ловкости»).
Лимит поднимается сам, как только заполнена вторая стойка.

**Заливка = состояние**: не взят — тёмная заливка и контур цвета стойки вполсилы; взят — сплошная
заливка цветом стойки и светлый контур; на превью-пути — золотой контур. Кейстоуны переворачиваются
в золото целиком. Подписи есть только у стартов, разблокировок, нотаблов и кейстоунов — малые узлы
и сокеты подписей не получают, иначе колесо превращается в кашу.

**Направляющие** (кнопка `Guides`) — геометрия колеса из черновика: шесть секторов по 60° своими
цветами (три луча и три клина), кольца R0 70 / R1 215 / R2 385 / R3 520 пунктиром и свечение ядра.
Это ориентир для глаза и руки: узлы к ним не липнут, в данные они не попадают.

## Управление

Режим переключается кнопками в шапке — видимое состояние вместо комбинаций модификаторов.

| | |
|---|---|
| колесо | зум к курсору |
| средняя / правая кнопка + тяга | панорама |
| `F` | вписать дерево в экран |
| `Delete` | удалить выделенное |
| `Esc` | снять выделение / отменить связывание |
| `Guides` | показать/скрыть кольца и секторы колеса |

**Select** — клик выбирает, тяга двигает, тяга по пустому месту — рамка выделения,
`Shift`/`Ctrl` — добавить к выделению. `Ctrl` при перетаскивании — привязка к сетке 25.

**Add** — клик открывает под курсором список классов; выбранный класс и создаётся на месте клика.
Класс заранее выбирать не нужно. В строках меню сразу видно, какой id получит узел.
`Shift`+клик пропускает меню и повторяет последний класс — прогон кластера снова стоит один клик
на узел.

Новый узел **наследует предыдущий узел своего класса**: выделенный, если он того же класса; иначе
последний созданный; иначе — последний узел этого класса в дереве, чтобы серии имён переживали
перезагрузку файла. Наследуется:

* **id** — следующий номер той же серии: назвали первый узел кластера `small_strength_1`, дальше
  сами пойдут `small_strength_2`, `_3`. Шаблон без номера начинает серию (`armor_hub` →
  `armor_hub_2`), ведущие нули сохраняются (`node_01` → `node_02`);
* **стойка** — всегда, даже когда шаблона этого класса ещё нет: тогда стойка берётся у выделенного
  узла, чтобы луч не приходилось выставлять каждому узлу заново;
* **заголовок, заметка и все строки модификаторов** — кластер это и есть прогон почти одинаковых
  узлов, так что первый узел настраивается один раз, а остальные набиваются кликами.

`abilityId` **не наследуется никогда** — он уникален для узла, и унаследованная ссылка на чужую
способность выглядела бы правдоподобно. Пустое поле находит `Check`, подменённое — нет. По той же
причине у узлов со способностью (разблокировка, сокеты, старт) не наследуются заголовок и заметка.

Если выделен ровно один узел, новый **сразу связывается с ним** — цепочка набивается повторными
кликами, без переключения в Link.

**Link** — клик по двум узлам. Если связь есть — разрывает, если нет — создаёт.

**Simulate** — клик берёт или возвращает узел. Наведение на невзятый узел показывает **самый
дешёвый путь до него** золотым пунктиром и цену в очках в статусной строке; `Ctrl`+клик берёт весь
путь целиком (всё-или-ничего: путь, не влезающий в бюджет, не берётся частично).

Наведение на узел показывает карточку у курсора: заголовок, способность (если узел на неё ссылается),
строки модификаторов и заметка. Строки форматирует **`Core.Localization.ModifierFormatter`** —
те же шаблоны `Modifier_Flat/Increase/Multiplicative` из .po и те же единицы параметров из
`SharedData/Formatting/ParameterFormats.json`, что и в тултипе предмета. Строка в карточке читается
ровно так, как прочтётся в игре; условие показывается в скобках и не прячется.

Переименование узла в поле **Id** применяется по Enter и при уходе из поля. Занятый id не
применяется — поле возвращает прежнее значение.

Панель справа: **Node** (свойства), **Totals** (итоги), **Base** (базовые статы персонажа).
**Check** показывает проблемы содержания: недобор/перебор строк, узел без способности, точка
старта без стойки, висящий узел, число точек старта ≠ 3. Это отчёт, а не запрет — инструмент
всегда даёт сохранить незаконченное дерево.

## Правила симуляции

* Каждый узел стоит 1 очко; три точки старта даны бесплатно и взяты изначально.
* Узел можно взять, только если он смежен с уже взятым. Распределение может быть тремя
  несвязанными островами — каждый растёт от своей точки старта.
* Узел можно вернуть, только если после этого ничего не повиснет в воздухе: каждый оставшийся
  взятый узел должен доходить до какой-нибудь точки старта через взятые узлы. Разматывание с концов.
* Бюджет настраивается в шапке правой панели. Сброс — кнопка **Reset allocation**.
* Золото, жетоны отката и цена респека не моделируются — это игровая экономика.

Если в дереве нет узлов `Start`, взять нельзя ничего: правило связности держится строго, и
инструмент говорит об этом в статусной строке, а не подменяет правило.

## Сумматор

Считает **настоящей формулой игры**: собирает реальные `Core.Modifiers.SimpleModifier` и зовёт
`Core.Calculations.CalculateFloatValue`, то есть

```
итог = (база + Σ Flat) × (1 + Σ Increase) × (1 + Σ Multiplicative)
```

с тем же клампом снизу нулём, что и в бою. Панель показывает по каждому затронутому параметру
суммы трёх вёдер отдельно и итог — подозрительное число можно проследить до ведра, которое его дало.

Базовые значения персонажа взяты из `Main/Player/Player.cs` → `GetUnarmedBaseValue` и вынесены во
вкладку **Base**: любой параметр правится, чтобы прикинуть дерево поверх конкретной экипировки.
Профиль переживает перезапуск (`editor-settings.json`).

Условные модификаторы считаются как безусловные — у инструмента нет боевого состояния, чтобы
проверить условие, — но помечаются: в строке параметра стоит `(N cond.)`, под таблицей общий счёт.

Кейстоуны в сумматоре — строки текста: их правила не данные, а хуки в боевом пайплайне.

## Чего инструмент не делает

* Не интегрируется в игру, не трогает `Main`, `Battle`, `Crafting`, `LootGeneration`.
* Не реализует боевые механики и не исполняет правила кейстоунов.
* Не содержит контента: дерево пустое, раскладка кластеров из черновика — ориентир, не данные.
* Нет отмены действий (`Ctrl+Z`). Страховка — git и то, что сохранение детерминировано.
* Переименование узла сбрасывает его из текущего распределения (id — это идентичность узла,
  распределение адресуется по id).
